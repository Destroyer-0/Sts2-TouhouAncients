#### 选项池体系（`TARelicOptionPools`）

先古之民的选项生成已由基类 `TouhouAncientBase` 接管，**不使用** BaseLib 的 `MakeOptionPools` / `AncientOption<T>` /
`AddCustomAncientSpawnCondition`（这些机制在本项目已停用；`MakeOptionPools` 仅为满足 BaseLib 抽象成员而保留的兼容来源）。
子类只重写一个属性：

```csharp
protected override IReadOnlyList<TARelicOptionGroup> TARelicOptionPools =>
[
    CreateTARelicOptionPool(           // 第一个选项：三选一
        TARelicOption<HakureiGohei>(),
        TARelicOption<SubspaceHole>(),
        TARelicOption<HakureiAmulet>()
        ),
    CreateTARelicOptionPool(           // 第二个选项：二选一
        TARelicOption<MiniShrine>(),
        TARelicOption<DonateMoneyBox>()
        )
];
```

- **一行一个池，写几行就是几个选项**，池数不受 BaseLib「1/2/3 个池」的限制。
- **一池多个选项**：写成 `(池, N)`，例如 `[(MainPool, 3)]` 表示从 `MainPool` 不重复抽 3 个；
  `[(TreasurePool, 2), RemainderPool]` 表示前两个选项从宝物池抽、第三个从另一个池抽。
- **权重**：`TARelicOption<T>(weight)`，如 `TARelicOption<FirmamentSash>(3)`；传 `0` 表示不出现。
- **闪红等原版标记**：`TARelicOption` 已转发原版链式方法，就地书写即可，可与权重任意顺序：
  `TARelicOption<HotokeMishiIshiNoHachi>().ThatDecreasesMaxHp(30m)`。
  另有 `ThatDoesDamage` / `ThatWillKillPlayerIf` / `ThatHasDynamicTitle` / `ThatWontSaveToChoiceHistory` / `WithOverridenHistoryName`。
- **生成前准备数据**（对应原 BaseLib 的 `ModelPrep`）：`TARelicOption<IridescentDream>().Prep((IridescentDream relic) => { ... })`，
  lambda 必须写参数类型（否则推断不出泛型参数）。
- **条件**：遗物重写 `CanAppear(Player?)`（返回 false 则该遗物不进候选），基类在抽取前统一过滤。
- **去重**：同一次事件内同一遗物不会出现两次（跨池全局去重）。
- **挑战选项**：不进池、不参与抽取与去重，由基类固定追加在末尾（见 §7.1）。
- **图鉴 / 控制台 / 调试选项**：`AllPossibleOptions` = 全部池的候选 + 挑战选项；
  子类**不要重写** `GenerateInitialOptions()` / `AllPossibleOptions`，也不要自行拼装选项，否则条件过滤、去重与挑战奖励收集会失效。

#### 第一幕（Act 1）先古之民

本 Mod 支持第一幕先古之民，与第一幕原生候选（原版涅奥；其他库按幕注入的先古之民）
同池均匀抽取（各占 `1/(N+1)`，N 为池内候选数）。

- **为什么需要专门处理**：原版 `ActModel.GenerateRooms` 的候选是
  `GetUnlockedAncients(unlockState).Concat(_sharedAncientSubset ?? [])`，而 `_sharedAncientSubset`
  只对第二幕及之后有值（原版 `RunManager.GenerateRooms` 里 `State.Acts.Skip(1)` 才调
  `SetSharedAncientSubset`）；第一幕的 `AllAncients`（`Overgrowth` / `Underdocks`）又硬编码为单元素列表
  （涅奥）。因此 BaseLib 的 `AddCustomAncientsToPool` 与 `IsValidForAct` 都够不到第一幕。
- **接管位置**：`scripts/Patches/Act1AncientPoolPatch.cs`，Transpiler 于 `ActModel.GenerateRooms`：
  - 在 `callvirt GetUnlockedAncients(UnlockState)` 之后插入 `ldarg.0` + `call AppendAct1Ancients`；
  - 插入后仅当 `act.Index == 0`（第一幕）时，把本 Mod 中 `ShowAct == 1` 且未被禁用的
    先古之民追加到候选末尾；追加前按 `Id` 去重、候选按 `Id.Entry` 排序
    （`NextItem` 按下标抽取，顺序必须各端一致）。
  结果：原版 `rng.NextItem` 自动把它们与涅奥同池均匀抽取，**不需要重抽、不需要派生 RNG、
  不打乱原版随机流**；二/三幕与共享池完全不碰。
- **为什么 patch `GenerateRooms` 而不是各幕的 `GetUnlockedAncients`**：
  - 后者在 `ActModel` 上是 `abstract`、每个幕各一份实现（原版 4 个幕 + 其他 Mod 的幕），
    想劫持全部幕就必须在启动期反射枚举 `ModelDb.AllAbstractModelSubtypes`；
  - 前者在基类上只有**一个非抽象实现**（`public void`，子类不可 override），patch 它就等于
    覆盖所有幕——`GetUnlockedAncients` 是虚调用，会自然派发到各幕自己的实现。
  - 附带好处：不枚举 Mod 类型（避开 `ReflectionHelper.ModTypes` 在 ModManager 初始化完成前
    抛异常的坑，也不会连带中断 `Entry.Init()`）、不依赖挂载时机（无需额外 Bootstrap 类）。
  - 代价：依赖原版 `GenerateRooms` 的 IL 结构（`GetUnlockedAncients` 调用点）；
    未命中时只 `Log.Error` 不抛异常，第一幕注入静默失效。同文件同锚点风格的参考：`BanAncientPatch`。
  - 注入位置在 `Concat(_sharedAncientSubset)` **之前**，所以 `BanAncientPatch` 在 `Concat` 之后
    插入的过滤逻辑会一并对追加的先古之民生效。
- **新增一层先古之民**：只要在 `TouhouAncientBase` 子类里写 `ShowAct => 1` 即可被自动纳入，
  无需再改补丁；`ShowAct == null`（二/三层通用）的先古之民不会进第一幕。
- **其他 Mod 的一层先古之民不由本补丁收集**：BaseLib 没有一层注入通道（`AddCustomAncientsToPool`
  要求 `_sharedAncientSubset != null`，而第一幕它恒为 null，所以直接 return），只声明
  `IsValidForAct` 不会让它出现在第一幕；对方若自行 patch `GenerateRooms`（BaseLib 与 RitsuLib
  都是这么做）就会自动参与同池抽取。多套注入同时存在时靠 `Id` 去重，不会把同一个先古之民算两次概率。
- **禁用涅奥**：设置界面「初始先古之民配置」区域的 `BanNeow`（禁用掩码第 23 位）由
  `BanAncientPatch` 的 Transpiler 生效——它在 `GenerateRooms` 里 `Concat` 之后过滤整个候选列表，
  所以涅奥被禁用时直接从池里消失。
- **禁用本 Mod 的一层先古之民**（如哆来咪·苏伊特）：由 `CollectAct1Ancients` 里的
  `TouhouAncientsConfig.IsAncientBanned(type)` 跳过追加，无需改补丁。
- **跨幕去重**：`ShowAct == 1` 的先古之民在二/三幕会被 `IsValidForAct`
  （`act.ActNumber() == ShowAct`）判定为非法，由 BaseLib 的 Prefix 剔除，不会跨幕重复。
- **与图鉴的关系（注意行为差异）**：`NRelicCollectionCategory.LoadRelics` 用两套集合：
  `AllAncients`（决定列出哪些条目）与 `GetUnlockedAncients`（决定条目是否已解锁、显示真名还是
  `UNKNOWN_ANCIENT`）。本补丁只改 `GenerateRooms` 的局部变量，**不影响这两者**，所以图鉴里
  一层先古之民的分类完全由 BaseLib / RitsuLib 自己的注入决定，与本补丁无关。
- **通用教训**：任何在 `TargetMethods()` / `TargetMethod()` 里枚举 Mod 类型
  （`ModelDb.AllAbstractModelSubtypes`、`ReflectionHelper.ModTypes` 等）的补丁，在 `Entry.Init()`
  阶段求值都会抛「ModManager is not finished initializing!」，并连带中断后面所有初始化；
  优先考虑改为 patch 基类的非抽象方法（如 `ActModel.GenerateRooms`）。
  只写 `[HarmonyPatch(typeof(具体类型), "具体方法")]` 的补丁不受影响。
- **涅奥专属表现**：`TouhouAncientBase.BeforeEventStarted` 中当 `ShowAct == 1` 时复刻涅奥两步
  （非读档时先 `SetCurrentHpInternal(0m)` 再靠 base 回满，随后 `NRun.Instance.GlobalUi.TopBar.Hp.LerpAtNeow()`）。
  用 override 而非 Transpiler，因为 `BeforeEventStarted` 是 async，逻辑在状态机 `MoveNext` 里。

#### 1.8.1 SmartFormat 动态文本（只能用本体已注册的格式化器）

本体 `LocManager.LoadLocFormatters` 只注册了 `plural`、`cond`、`choose`、`substring`、`ismatch`、`localeNumber`、`default`、`abs`、`energyIcons`、`starIcons`、`highlightDifferences`（含反向）、`percentMore`、`percentLess`、`showIfUpgraded` 等格式化器。**不能自创格式化器名**（例如 `{multiplayer:你们|你}`）：`LocString.GetFormattedText()` 会抛出 `FormattingException`，被 `LocManager.SmartFormat` 捕获后**原样返回占位符文本**，玩家会直接看到 `{multiplayer:你们|你}` 这串字符。

常用写法（`{}` 表示变量自身的值）：

| 需求 | 本地化文本写法 | 代码侧 |
|------|----------------|--------|
| 单/多人称呼二选一（不随语言文化变化） | `{PlayerCount:choose(1):你\|你们}` | `locString.Add("PlayerCount", base.Creature.CombatState?.Players.Count ?? 1);` |
| 布尔分支（true 分支在前、false 分支在后） | `{IsMultiplayer:你们\|你}`（可写成 `{Var:cond:你们\|你}`） | `locString.Add("IsMultiplayer", 玩家数 > 1);` |
| 条件拼接整段文本（为真时输出） | `{CardTitles.StringValue:cond:\n\n微缩：\n{}\|}` | 传入字符串变量 |
| 复数（受语言文化影响：中文只有 other 类别，zhs 下恒选复数分支，慎用） | `{Count:plural:card\|cards}` | `locString.Add("Count", n);` |
| 升级差值显示 | `{Amount:diff()}` | 由 `DynamicVar` 自动带入 |

要点：
- 变量必须由代码 `Add` 进去，本体不会自动注入全局变量；变量缺失时 `choose` 无法命中分支键，会一直走默认分支。
- `choose` 按值的文本形式匹配分支键，`{Amount:choose(1):...}` 这类写法在本体与模组中均可用。
- BBCode 富文本标记（`[gold]`/`[blue]`/`[purple]`/`[red]`/`[green]`/`[jitter]`）在 SmartFormat 之后渲染，标记可以包在 `choose` 表达式外侧。

#### 1.8.2 怪物台词（TalkCmd.Play）

```csharp
TalkCmd.Play(line, base.Creature, VfxColor.Purple, VfxDuration.VeryLong);
```

- `line` 为 `new LocString("monsters", "TOUHOUANCIENTS-XXX.banter")`。需要变量的台词要**新建 LocString** 再 `Add`，不要用 `static readonly` 复用（避免变量互相污染）；无变量的台词可以 `static readonly`。
- 命名空间：`LocString` 在 `MegaCrit.Sts2.Core.Localization`，`VfxColor` / `VfxDuration` 在 `MegaCrit.Sts2.Core.Nodes.Vfx`。
- 时长：不传 `VfxDuration`（默认 `Custom`）时按文本字数自动计算（快速模式 0.1 秒/字，普通 0.12 秒/字），最短 0.5 秒。
- 播放时机：
  - 战斗开场：`public override Task BeforeCombatStart()`（所有怪物的显示节点已生成、开战横幅与首回合之前触发）。
  - 招式台词：放在对应 `XxxMove` 方法开头。
  - 仅首次播放：用 `bool` 字段标记（如辉夜 `_eternalNightReturnBanterPlayed`）；状态机循环里重复出现的招式不加标记会每次重复播报。
- `TalkCmd.Play` 在 `speaker.IsDead` 时直接返回 `null`；需要死亡瞬间播报时改用直接创建气泡（参考 `YorigamiJoonMonster`）。
- 角色差分：辉夜（`HouraisanKaguyaMonster`）的常规台词在**单人模式且唯一玩家为妹红**时整体跳过，判定见私有属性 `ShouldSkipBanter`（`CombatState.Players.Count == 1` 且 `Players[0].Character.Id.Entry` 含 `MOKOU`，忽略大小写），所有播报统一走私有方法 `PlayBanter(LocString line)`；妹红的彩蛋台词由 `HouraiPuzzleCard` 使用 `MOKOU_BANTER` / `MOKOU_BANTER2` 单独播放，避免两套台词混播。

描述里用 `{DynamicVarName}` 绑定 `CanonicalVars`；升级差值用 `{VarName:diff()}`。

生命相关用语统一 **最大生命**，不要写「体力上限」。

遗物拾起并附魔时的中文格式：

```text
拾起时，（其他效果），从[gold]牌组[/gold]中选择一张(指定类型的)牌，为它[gold]附魔[/gold]：[purple]{EnchantmentName}[/purple]。
```

附魔名用 `StringVar` 的 `{EnchantmentName}`，不要硬编码。

#### 有值 / 无值的双分支文本（`cond:`）

`StringVar` 的默认值是空串 `""`（`StringVar(string name, string baseValue = "")`，且 `ToString()` 返回 `StringValue`），
所以「运行时才知道具体是什么」的文本可以用 SmartFormat 的 `cond:` 做双分支：未赋值时（事件界面预览）显示泛化文本，
赋值后（拾起时）显示具体名称。原版 `ArchaicTooth`（古老牙齿）与 `TouchOfOrobas`（欧洛巴斯之触）用的就是这个写法。

```text
{变量名.StringValue:cond:非空时显示的文本|为空时显示的文本}
```

原版 zh 文本（可直接照抄句式）：

```json
"ARCHAIC_TOOTH.description": "拾起时，将{StarterCard.StringValue:cond:[gold]{StarterCard}[/gold][gold]变化[/gold]为[gold]{AncientCard}[/gold]|一张初始卡牌[gold]变化[/gold]为先古版本}。",
"TOUCH_OF_OROBAS.description": "拾起时，将{StarterRelic.StringValue:cond:[gold]{StarterRelic}[/gold]替换为[gold]{UpgradedRelic}[/gold]|你的初始[gold]遗物[/gold]替换为[gold]先古[/gold]版本}。"
```

本 Mod 用例：`IRIDESCENT_DREAM`（虹光之梦）。

### 2.6 添加新 Ancient 时

1. `scripts/ancients/{Name}Ancient.cs`，继承 `TouhouAncientBase`
2. `TouhouAncientsConfig.ForcedAncientOption` 加枚举，并在 `IsAncientForced` 里接线
3. `localization/*/settings_ui.json` 加配置标题
4. 重写 `IsValidForAct`（只留幕数）和 `ShouldForceSpawn`（读 Force）
5. 禁用选项由 `BanAncientPatch` 自动扫描，**不必**再手写 Ban 配置
6. 若有挑战：重写 `ChallengeEncounter`，并补 Encounter / Monster / 场景 / 图鉴列表。`ModelDbAllEncountersPatch` 会自动扫描 `TouhouAncientEncounter` 子类，不必再手写遭遇列表
7. 图标路径目前每个 Ancient 手写四条 `CustomMapIconPath` 等（约定见 1.9）

#### 遗物选项的动态文本：必须在选项生成阶段就填好

如果某个 Ancient 遗物的描述里含有依赖当前对局的内容（例如「替换掉你的初始遗物」这种需要写出具体遗物名的文本），
该内容**必须在事件选项生成阶段确定**，不能等到 `AfterObtained`。

原因：事件界面在玩家拾起之前就会渲染遗物描述。`AfterObtained` 是在 `RelicCmd.Obtain` →
`player.AddRelicInternal` 之后才调用的，那时文本早已渲染过一遍，`StringVar.StringValue` 还是空串，
描述里只会一直显示 `cond:` 的兜底分支。

钩子是候选构造阶段的 `Prep`（对应原 BaseLib 的 `ModelPrep`，在选项生成、抽取之前的候选构造时调用）：

```csharp
CreateTARelicOptionPool(
    TARelicOption<IridescentDream>().Prep((IridescentDream relic) =>
    {
        if (Owner != null) relic.SetupForPlayer(Owner);
    }),
    /* ... */
)
```

配套写法（参照原版 `TouchOfOrobas` / `ArchaicTooth`）：

- 把目标存进 `[SavedProperty]`（`ModelId?` 或 `SerializableCard?`），这样读档时 setter 会重新执行；
- 在**属性 setter** 里重建 `StringVar.StringValue` 与 `_extraHoverTips` —— 克隆与读档都能自动恢复；
- `AfterCloned()` 里重置 `_extraHoverTips` 后，靠 `SetupForPlayer` 再次赋值触发 setter 重建；
- 该方法**不要**用遗物自身的 `Owner`（此阶段尚未设置），必须由调用方传入玩家，
  在 ancient 里就是 `Owner`（即 `AncientEventModel.Owner`，可能为 null，需判空）。

## 4. 内容类型开发规范

### 4.1 遗物

```csharp
[Pool(typeof(SharedRelicPool))]
public class Xxx : TouhouAncientRelics
{
    // 拾起：HasUponPickupEffect + AfterObtained
    // 战斗 Hook：直接重写虚方法
    // 多人：每个 Hook 检查 player != base.Owner（或等价 Owner 判断）
}
```

图标由基类按类名解析（`res://images/icon/relics/{类名}.png`，大图标 `IconLarge/{类名}.png`，找不到时回退 `default.png`）。休息处触发参考原版 `EternalFeather`：`AfterRoomEntered` + `room is RestSiteRoom`。

地图路线/节点标记（参照原版 `FurCoat`，参考实现 `Mamizou/DragonVeinVessel`）：

- `AfterObtained` 记录 `[SavedProperty] int ...ActIndex`（拾起时的幕），并用 `new Rng(Owner, Id)`（`MegaCrit.Sts2.Core.Random`）确定性随机，不污染主线随机
- `point.AddQuest(this)`（`MegaCrit.Sts2.Core.Map`）在节点上打标记，地图会显示小图标（`NMapPoint` 的 `Quests`）
- 坐标存入 `[SavedProperty] int[] ...CoordCols / ...CoordRows` + `bool ...CoordsSet`，读档/地图重生成时在 `ModifyGeneratedMapLate` 里 `map.GetPoint(coord).AddQuest(this)` 恢复
- 判定当前节点是否被标记：`RunState.CurrentMapPoint.coord` 与保存坐标比对（`MapCoord` 为 struct，可用 `==`/`Contains`）
- `MapPoint.Equals` 是 private（类外是引用比较），比较节点请用 `coord`

### 4.2 附魔

继承 `TouhouAncientEnchantmentModel`。可重写 `CanEnchantCardType`、`CanEnchant`、`OnEnchant`、`OnPlay`。

仅 Attack：`CanEnchantCardType(CardType cardType) => cardType == CardType.Attack`。  
排除 X 费：`card.EnergyCost.CostsX` / `card.HasStarCostX`。  
进入弃牌堆：`card.Pile?.Type == PileType.Discard`，并用 `oldPileType != PileType.Play` 排除正常打出。

从 `ModelDb` 牌池（`GetUnlockedCards` 等）筛候选时，返回的是 **canonical 模板**，不要调 `CanEnchant`。`CardModel.Owner` 会 `AssertMutable()`；其他模组给 `CanEnchant` 打的 Harmony 补丁也可能读 `Owner`，从而 `CanonicalModelException`。池子过滤只用模板上安全的字段（`CanEnchantCardType`、`CanonicalStarCost`、`HasStarCostX`、`Tags`、`CanBeGeneratedInCombat` 等）。`CardFactory.GetDistinctForCombat` 生成带 Owner 的战斗实例后，再对那张可变卡调 `CanEnchant`。

附魔会进战斗 Hook 监听器，可重写 `AfterDamageGiven`、`BeforeDamageReceived` 等全局 Hook。独有 Hook：`OnPlay`、`AfterCardPlayed`、`BeforeFlush`、`AfterCardChangedPiles`、`BeforeCardRemoved`。

无 `[SavedProperty]` 的附魔不必在 `Entry.cs` 注册。

一次性效果用 `base.Status = EnchantmentStatus.Disabled`（需 `MegaCrit.Sts2.Core.Entities.Enchantments`），不要自己做 `_hasTriggered`。

多人同步：**反射枚举（如 `ModelDb.AllAbstractModelSubtypes`）的顺序依赖程序集/类型加载顺序，联机各端不保证一致**。若用它构造候选列表再做 `UnstableShuffle(rng)`（结果依赖列表初始顺序），即使 Rng 流同步，各端也会随机到不同结果。必须在构建缓存时按 `ModelId` 确定性排序：`list.OrderBy(e => e.Id.ToString(), StringComparer.Ordinal).ToList()`（原版 `ModelDb` 亦用 `orderby ... Id.Entry`）。参考 `Yumeiro.cs` 的 `AllEnchantments`。

### 4.3 卡牌

- 继承 `TouhouAncientCards`（`abstract`）
- **具体类必须有 `public` 无参构造函数**，链到 `base(energyCost, type, rarity, targetType, shouldShowInCardLibrary)`
- 基类无参构造器目前是注释掉的，不要依赖它
- 常量放类顶部 `private const`
- `[Pool(typeof(EventCardPool))]` 需要 `using BaseLib.Utils;` 与 `using MegaCrit.Sts2.Core.Models.CardPools;`
- 无需在 `Entry.cs` 注册
- `OnUpgrade` 里用 `base.DynamicVars["Key"].UpgradeValueBy(...)`，不要改 Canonical 默认值字段

```csharp
[Pool(typeof(EventCardPool))]
public class ExampleCard : TouhouAncientCards
{
    private const int energyCost = 1;
    private const CardType type = CardType.Skill;
    private const CardRarity rarity = CardRarity.Ancient;
    private const TargetType targetType = TargetType.Self;
    private const bool shouldShowInCardLibrary = true;

    protected override IEnumerable<DynamicVar> CanonicalVars =>
    [
        new DynamicVar("Damage", 8)
    ];

    public ExampleCard() : base(energyCost, type, rarity, targetType, shouldShowInCardLibrary) { }

    protected override async Task OnPlay(PlayerChoiceContext choiceContext, CardPlay cardPlay) { }

    protected override void OnUpgrade()
    {
        base.DynamicVars["Damage"].UpgradeValueBy(3m);
    }
}
```

| Hook / 成员 | 说明 |
|-------------|------|
| `OnPlay` | 打出效果 |
| `OnUpgrade` | 升级改 DynamicVars |
| `GetResultPileType` | 弃牌去向；回手返回 `PileType.Hand` |
| `GetResultPileTypeForCardPlay` | Quest/能力打出后移出战斗用 `PileType.None` |
| `CanPlay` / `IsPlayable` | 打出限制。**新增**限制优先覆写 `IsPlayable`；破除诅咒/灼伤禁打才用 Harmony Patch `CanPlay` |
| `CanonicalKeywords` | 固有/保留/虚无等 |
| `ExtraHoverTips` | 额外悬停 |
| `BeforeFlush` | 手牌检测阶段改费用 |
| `AfterCardEnteredCombat` | 卡牌**已进入**战斗牌堆后触发（`CardPileCmd.Add` 里 `AddInternal` 之后、`oldPile == null && targetPile.IsCombatPile` 时）。适合做"生成后自动配对"逻辑（如封魔阵进弃牌堆自动找目标牌）。此时 `card.Pile` 已是目标牌堆 |
| `AddExtraArgsToDescription` | 覆写描述动态变量：往里 `description.Add("Key", value)`，覆盖 CanonicalVars 的默认值。可实现"非战斗/战斗已配对/战斗未配对"三态描述（SmartFormat 条件只能二选一）。**文本必须从本地化表读取**（如 `new LocString("cards", Id.Entry + ".descriptionIdle")`），不要硬编码中文，否则无法多语言。参考 `SealCircle` |

费用：`EnergyCost.AddThisTurn(n)`；`SetThisTurn` / `SetThisCombat`。  
辉星：`SetStarCostThisCombat(0)` / `SetStarCostThisTurn(0)` / `SetStarCostUntilPlayed(0)`。  
重放：`card.BaseReplayCount++`；实际次数 `GetEnchantedReplayCount() + 1`。

目标：`None` / `Self` / `SingleEnemy` / `AllEnemies` / `AnyCreature` / `AnyEnemy`。  
类型：`Attack` / `Skill` / `Power` / `Curse` / `Quest`。  
稀有度常用 `CardRarity.Ancient` 或 `CardRarity.Quest`。

> **注意**：`AfterCardGeneratedForCombat` 是给**生成者**监听的 Hook（creator 是玩家；敌人施加状态牌时 creator 为 null，且文档明确排除敌人施加的状态牌），**不适合**在"敌人生成的状态牌自身"上做逻辑。要监听"牌自己被放进战斗牌堆"，用 `AfterCardEnteredCombat`。

### 4.6.1 怪物演出（灵梦灵符参考）

帧动画怪物做"技能演出 + 场景子节点动画"的参考实现：

- **视觉辅助脚本**：新建继承 `NCreatureVisuals` 的类（如 `scripts/Vfx/HakureiReimuVisuals.cs`）挂在 `creature_visuals/{怪物}.tscn` 根节点，`[Export]` 场景子节点引用（如 `AmuletRoot`），在 `_Ready` 中 `base._Ready()` 后缓存子节点（`GetNodeOrNull<AnimatedSprite2D>`）。怪物侧用 `base.Creature.GetCreatureNode()?.Visuals as HakureiReimuVisuals` 获取。
- **运行时建逐帧动画**：`new SpriteFrames()` + `AtlasTexture { Atlas, Region }` + `AddFrame("default", atlas)`，`SetAnimationSpeed` / `SetAnimationLoop` 控制播放；`AnimatedSprite2D` 没有 `Loop` 属性，必须用 `SpriteFrames.SetAnimationLoop`。
- **切换动画保持当前帧**：`AnimatedSprite2D.Animation` 切换会重置帧，先记录 `amulet.Frame`，切完 `Mathf.Min(当前帧, 新动画帧数-1)` 恢复。
- **位移演出**：`CreateBodyMoveTween(body)`（基类提供，死后自动锁回原位）+ `TweenProperty(body, "position", ...)`；子节点（灵符）直接 `CreateTween().TweenProperty(amulet, "global_position", ...)`，用 `AwaitFinished`（`MegaCrit.Sts2.Core.Nodes.GodotExtensions`）等待完成。
- **禁止受击动画**：重写 `ShouldPlayHurtAnimation => !_isAnimating`，演出开始时置位、结束后复位。
- **坐标系**：`creature_visuals` 根（NCreatureVisuals）与 `NCreature` 原点一致（`Visuals.Position = Vector2.Zero`），场景内 Marker2D（CenterPos/灵符目标）的 `GlobalPosition` 与 `creatureNode.VfxSpawnPosition` 同坐标系，可直接互算。
- **意图位置**：战斗里真正画意图的是 `NCreature.IntentContainer`（`%Intents`），和 `Visuals` 是兄弟节点。原版只在私有 `UpdateBounds` 里执行 `IntentContainer.Position = IntentPos.Position - IntentContainer.Size / 2f`（用 Marker 的本地 `Position`，不乘 `Visuals.Scale`）。`ScaleTo` 不会调用 `UpdateBounds`。改 `IntentPosition.GlobalPosition` 不会让图标跟着动；缩放后要意图跟着走，直接写 `IntentContainer.Position`。身体节点用 `NCreature.Body` / `Visuals.GetCurrentBody()`，`NCreatureVisuals` 没有 `Body`。参考 `BloodDisasterPower.ChangeAmount`。
- **坑**：在继承 `NCreatureVisuals` 的脚本类里 `AddChildSafely`/`QueueFreeSafely`（`MegaCrit.Sts2.Core.Helpers.GodotTreeExtensions`）可能报 CS0103（Godot 源生成器上下文问题），改用 `AddChild`/`QueueFree` 原始 API。

### 4.6.2 怪物演出（辉夜五道难题漂浮谜题参考）

怪物周围"漂浮环绕物品 + 按进度淡出"的参考实现（`scripts/Vfx/HouraisanKaguyaVisuals.cs` + `scenes/creature_visuals/HouraisanKaguyaMonster.tscn`）：

- **环绕旋转动画**：tscn 内联 `sub_resource type="Animation"`（`loop_mode=1` 循环，`resource_name` 与键一致）+ `AnimationLibrary`（含 `RESET` 空动画与主动画）+ 节点段挂 `AnimationPlayer`（`libraries = {&"": SubResource(...)}`）。动画不设 `autoplay`，由脚本在技能释放时 `PuzzleAnimPlayer.Play("puzzle_orbit")` 启动。
- **远近变化**：绕椭圆轨道做 `position` 关键帧（8 采样/圈，`tracks/N/type="value"`，`values` 为 `Vector2` 数组），每个物品各一条 `scale` 轨道与椭圆纵向位置联动（近处大、远处小），相位错开（如 5 个物品各偏移 72°）形成环绕流动感。`update: 0` 表示插值更新。
- **按进度淡出**：`Power → Monster → Visuals` 回调链（同 4.6.1）：Power 的 `CompletePuzzle` 内 `base.Owner.Monster is XxxMonster` 后调怪物方法 → 怪物查 Power 完成数（Power 暴露 `GetCompletedPlayerCount`）→ Visuals `UpdatePuzzleTransparency(puzzleType, completedCount, playerCount)`。多人按比例 `alpha = 1 - completedCount / playerCount`，全部完成时淡出后 `visible=false`。
- **淡入淡出**：`Sprite2D` 用 `modulate:a` 渐变（`CreateTween().TweenProperty(puzzle, "modulate:a", ...)`）。注意 `TweenCallback` 是 `Tween` 的方法，不能接在 `TweenProperty`（返回 `PropertyTweener`）后面链式调用，需先取 Tween 变量再分别调用。
- **开场隐藏**：根节点（PuzzleRoot）默认 `visible=false`，释放技能时才显示；`z_index` 高于怪物本体避免被遮挡。
- **节点悬停 HoverTip（多人显示未完成玩家）**：`NHoverTipSet.CreateAndShow(Control owner, hoverTips, alignment)` / `NHoverTipSet.Remove(owner)` 是全局 HoverTip 系统（`MegaCrit.Sts2.Core.Nodes.HoverTips`）。在每个谜题 Sprite2D 下挂子 `Control`（`mouse_filter=0` Stop，offset 定义命中矩形，随父 Sprite 变换缩放/旋转），Visuals 在 `_Ready` 连接 `MouseEntered/MouseExited`。进入时从怪物（`GetParent<NCreature>()?.Entity.Monster as XxxMonster`）查未完成玩家名（Power 暴露 `GetIncompletePlayerNames`），用 `LocString.Add("PlayerNames", ...)` 注入 SmartFormat 变量后 `CreateAndShow(hitbox, new HoverTip(desc), HoverTip.GetHoverTipAlignment(hitbox))?.SetFollowOwner()`；移出时 `Remove(hitbox)`。**坑**：`SetFollowOwner` 依赖 owner 与 HoverTip 的相对偏移（`CreateAndShow` 时 `SetAlignment` 先定位），不能配 `HoverTipAlignment.None`，否则 HoverTip 固定到原点。图标隐藏（visible=false）后子 Hitbox 随之失效，自然不可悬停。
- **坑**：新建 `.cs` 脚本的 `.uid` 文件需手动创建（格式 `uid://xxx` 单行）并填到 tscn 的 `[ext_resource type="Script" uid="..." path="..."]`，否则 Godot 打开场景会重新生成 uid 导致引用失配。

### 4.6.3 怪物能力状态演出（辉夜无实体半透明参考）

按"怪物是否拥有某个 Power"改变立绘透明度的参考实现（`scripts/monsters/HouraisanKaguyaMonster.cs`）：

- **事件订阅**：`Creature` 上有 `PowerApplied` / `PowerRemoved` 两个事件（`Action<PowerModel>`，`MegaCrit.Sts2.Core.Entities.Creatures.Creature`）。在 `AfterAddedToRoom` 里 `base.Creature.PowerApplied += AfterPowerApplied;` / `PowerRemoved += AfterPowerRemoved;`，并在 `BeforeRemovedFromRoom()`（可重写，基类默认空实现）里 `-=` 取消订阅，避免事件残留引用已结束战斗的怪物。原版 `TestSubject` 就是同一套写法（无实体时把自己变成 `StsColors.halfTransparentWhite`）。
- **订阅顺序**：事件要在施加 Power 之前订阅；施加后再调用一次刷新方法兜底（`PowerCmd.Apply` 内部会触发 `PowerApplied`，但顺序不宜依赖）。
- **透明度写入**：帧动画怪物直接改 `MyAnimatedSprite2D.Modulate` 的 alpha（保留 RGB：`Color color = sprite.Modulate; color.A = ...; sprite.Modulate = color;`）。场景里的子节点（如辉夜的 `PuzzleRoot`）会继承父节点 modulate，注意演出互不干扰。原版对 Spine 怪物用的是 `NCombatRoom.Instance?.GetCreatureNode(creature)?.GetSpecialNode<CanvasGroup>("%CanvasGroup")?.SetSelfModulate(color)`。
- **失去时机**：Power 层数归零时走 `Creature.RemovePowerInternal` → 触发 `PowerRemoved`，所以回合结束自然过期也能被捕获，无需额外处理回合钩子。
- **判空**：`MyAnimatedSprite2D` 在显示节点已回收（灾厄处决等）时会返回 null，写入前必须判空 + `GodotObject.IsInstanceValid`，否则异常冒出 Hook 会让战斗卡死。

### 5.8 AfterSideTurnStart 的 `participants`

`participants` **只包含当前回合行动的一方**，不是全场。敌人回合时玩家不在列表里。玩家侧遗物不要用 `participants.Contains(Owner.Creature)` 判断自己在不在场，改用 `side == Owner.Creature.Side`。曾因此导致 `DanmukuGhost` 失效。参考 `TwinSoulPower`。

### 5.9 Harmony 补丁要点

`harmony.PatchAll()` **只处理类上带 `[HarmonyPatch]` 的类型**。方法上还要有 `[HarmonyPostfix]` / `[HarmonyPrefix]` 等；光写 `[HarmonyPatch(...)]` 且方法名带 Postfix **不会**自动当 Postfix。参考 `NamelessYoukaiGlowPatch`。

指定卡牌可打出（破除 Unplayable）：Patch `CardModel.CanPlay`。`CurseBreakerQi` 对诅咒；`HinezumiNoKawagoromo` 对 `Burn`。

手牌红蓝流光：Postfix `CardModel.ShouldGlowGold` getter，再 Postfix `NHandCardHolder.UpdateCard` 换材质。shader：`res://shaders/nameless_youkai_flow.gdshader`。必须同步 `NCardHighlight` 私有字段 `_shaderMaterial`。

获得能量后钩子：Patch `PlayerCmd.GainEnergy(decimal, Player)`。Prefix `Priority.First` 把当前能量写入 `__state`；Postfix `HarmonyPriority(-1)` 把返回 `Task` 包一层，等原方法跑完（能量已加上）后由 `AfterEnergyGainedIfChanged` 构造 `PlayerEnergyGainContext`，再传给 `PlayerEnergyGainHook.AfterEnergyGained(context)` 分发。`amount <= 0` 不分发。回合开始 `ResetEnergy` / `AddMaxEnergyToCurrent` 不走 `GainEnergy`，仍用 `AfterEnergyReset`。叠装 RitsuLib 时两套钩子各自包装 Task、各自听众；本补丁 Postfix 优先级比 RitsuLib 的 `Priority.Last == 0` 更靠后，顺序不跟 Mod 列表走。不要让同一模型同时实现本接口和 RitsuLib `IPlayerResourceHookListener`。参考 `PlayerEnergyGainHookPatch`、`WindPriestessWine`。

### 5.12 回合奇偶

`combatState.RoundNumber % 2`。参考 `StageDevice`。

### 5.13 死亡预防

`ShouldDieLate` 返回 `false` 阻止死亡，再 `AfterPreventingDeath` 里治疗/扣最大生命。参考 `SoulButterfly`、`KonshiiNoKusuri`。

怪物死后只留尸体：不要把死掉的 `Creature` 留在敌人列表里（`PrepareForNextTurn`/`TakeTurn` 仍会跑）。可让 `ShouldCreatureBeRemovedFromCombatAfterDeath` 暂时 `false`，在自己的 `AfterDeath` 末尾 `CombatManager.RemoveCreature` + `combatState.RemoveCreature(creature, unattach: false)`，不要调用 `NCombatRoom.RemoveCreatureNode()` 直到要播 `NMonsterDeathVfx`。参考依神姐妹怪物。出招中途死亡时用 `unattach: true`，让原版 `PerformMove` 收尾的 `RemoveCreature` 因 `CombatState == null` 直接返回，避免二次移除。

帧动画怪物没有 Spine `attack_target_bone`，冲锋只能挪 `GetCurrentBody()`。`TouhouAncientMonsterBase.BeforeDeath` 会停位移 Tween、把身体拉回原位并播 `die`；死后 `PlayAnimation` / hurt 只允许 `die`。死后仍需播其它动画的怪物重写 `ShouldKeepAnimatingWhileDead`（紫苑双生）。位移用 `CreateBodyMoveTween` / `SetBodyPosition`。

### 5.13.1 回合接管（自动打牌）

参考 `WhisperingEarring`：在 `AfterAutoPrePlayPhaseEntered`（或 `Late` 版本）中自动打牌。要点：

- 打牌前先 `await card.SpendResources()`，再 `CardCmd.AutoPlay(choiceContext, card, target, AutoPlayType.Default, skipXCapture: true)`（`AutoPlay` 本身不扣能量，必须自己先花）。
- `CanPlay()` 会检查能量是否足够；每打一张重新扫描手牌（能量/手牌会变化）。
- 目标选择：`TargetType.AnyEnemy` 取 `combatState.HittableEnemies.FirstOrDefault()`；`AnyAlly` 取 `rng.NextItem(combatState.Allies.Where(...))`（空集合返回 null）；`AnyPlayer` 取自身。
- 按费用排序用 `card.EnergyCost.GetWithModifiers(CostModifiers.All)`，同费用保持手牌从左到右：`hand.Cards.Select((c,i)=>(c,i)).OrderByDescending(...).ThenBy(t=>t.index)`。
- 若 Power 要求"下回合才开始接管"：判断 `AmountOnTurnStart == 0`（`BeforeTurnStart` 每回合开头会把 `AmountOnTurnStart` 刷新为当前 `Amount`；当回合中途才添加的 Power 该值为 0）。
- 参考 `PossessedBySeigaPower`（走火入魔，霍青娥接管）、`WhisperingEarring`。

反序列化时 Owner 为 null；`RunState.AddCard()` 才设置。canonical 实例上不要假设 Owner 非空。

## 6. 注意事项

### 6.1 多人

每个会改状态的 Hook 检查所有权（`player != base.Owner` 或 `card.Owner`）。参考 Nina 遗物 `Yishixingqile`、`Yiyandingzhen`。动画用 `LocalContext.IsMine(card)` / `LocalContext.IsMe(player)`。

已经在某个 GameAction 里（例如 `await PlayerCmd.GainEnergy` 的续体、`AfterEnergyReset`）抽牌时，用 `ThrowingPlayerChoiceContext`。不要再 `new HookPlayerChoiceContext(..., GameActionType.CombatPlayPhaseOnly)`：一旦抽牌链路触发 `SignalPlayerChoiceBegun`，会再挂一层 Hook 动作，只有 `Owner.NetId == LocalContext.NetId` 的端会 enqueue，其它端等 `ExecutionStartedTask`，联机不同步。参考 `WindPriestessWine`。

### 6.2 脚本扫描

`abstract` 类不会被 Godot 脚本扫描器实例化。具体卡牌/遗物必须可被 `Activator.CreateInstance` 构造。

### 6.3 本地化名称匹配（替代 CardTag）

关键词放 `relics.json`，`LocString.GetFormattedText().Split(',')`，再对 `card.TitleLocString` 做 `Contains`。

### 6.4 MerchantEntry

`list.UnstableShuffle(rng).Take(N)`。商店刷新相关：`SuspiciousToken` + `MerchantRefreshEntry` + `NMerchantRefreshSlot`。

## 7. 大型专题

### 7.1 Ancient 挑战战斗

基类 `TouhouAncientBase` 已内置挑战选项。子类重写：

```csharp
public override SomeEncounter? ChallengeEncounter => ModelDb.Encounter<SomeEncounter>();
```

要点：

- 挑战选项不进池、不参与抽取与去重：由基类固定在选项末尾追加（见 §1.2「选项池体系」）
- **不要重写 `GenerateInitialOptions()` / `AllPossibleOptions`**：绕开基类会让条件过滤、去重与挑战奖励收集全部失效
- 进入战斗：`EnterCombatWithoutExitingEvent(encounter, rewards, shouldResumeAfterCombat: false)`，传入 **canonical** Encounter（v0.110.1+）
- 挑战是终点：不回事件页；`ShouldGiveRewards => true`；`TouhouAncientEncounter.TryModifyRewards` 只保留 `CombatRoom.ExtraRewards`
- Encounter 默认 `ShouldReceiveCombatHooks => false`，所以 `Entry.Init` 用 `ModHelper.SubscribeForRunStateHooks` 把当前 `TouhouAncientEncounter` 注册进 RunState Hook
- `shouldResumeAfterCombat: false` 使事件不完成，避免 `EventRoom.OnEventStateChanged` 自动存档把奖励弄丢
- 每个玩家事件实例只收集 **本玩家** `_generatedRelicOptions`，不要遍历全员合集再合并（会变成人数倍）
- 回血：`ChallengeRewardPatch` Patch `Hook.AfterCombatVictory`，且 `LocalContext.IsMe(player)`
- 读档恢复跳过重复全回血：`AncientChallengeRestorePatch` 在 `isRestoringRoomStackBase` 时 `MarkPreFinished()`
- **多人读档回奖励页**：挑战胜利后 `EndCombatInternal` 写入 `PreFinishedRoom = CombatRoom`（读档重建父事件 + pre-finished 战斗房并弹奖励页）。但 `EventRoom.OnEventStateChanged` 在事件"全员完成"时会 `SaveRun(this)` 把 `PreFinishedRoom` 覆盖成 EventRoom（先古事件），多人共享事件时序下存在误判窗口，导致奖励页退出重进回到先古页面。`AncientChallengeOnEventStateChangedPatch` 拦截 `EventRoom.OnEventStateChanged`：仅当 `TouhouAncientBase.ChallengeCombatEntered == true`（已进入挑战战斗）时跳过自动存档；该标志在 `StartChallenge` 置位、会话级不持久化，"无人投挑战按玩家拿遗物"分支不置位，正常事件照常存档 DONE 页
- `IsChallenge` 用置位-复位，避免污染 canonical
- 挑战按钮图标：`AncientDialoguePortraitPatch` 里 Patch `NEventOptionButton._Ready`；用 `RunHistoryIcon` 不要直接加载 path；宽图 `ResetIconSize`；识别靠 `TextKey.EndsWith(".fight")`，角色专属标题不要改 textKey
- 挑战选项标题：默认 `{AncientId}.fight.title`。角色彩蛋键为 `{AncientId}.fight.{token}.title`，当 `Character.Id.Entry` 包含该 token（忽略大小写）时启用，更长 token 优先。例如妹红 ID 含 `MOKOU` 时用 `fight.mokou.title`。之后只加本地化即可扩展，不必改代码。匹配逻辑在 `CharacterLocVariant`
- 挑战选项描述：`TOUHOUANCIENTS.fight.description`
- 遭遇失败文本：默认 `{EncounterId}.loss`。角色彩蛋键为 `{EncounterId}.loss.{token}`（同样用 `CharacterLocVariant`）。`GetLossMessageFor` 不是虚方法，由 `EncounterLossMessagePatch` Postfix。例如妹红打辉夜用 `HOURAISAN_KAGUYA_ENCOUNTER.loss.mokou`
- 挑战死亡会先被记成事件死亡（`Rooms.First()` 仍是 Ancient 事件）。`EncounterLossMessagePatch` 在 `CreateRunHistoryEntry` 后把 `KilledByEncounter` 改成该地图点最后一场 `TouhouAncientEncounter`，死亡引言才会走 `GetLossMessageFor`。`TouhouAncientEncounter.cs` 里旧的 `TouhouAncientEncounterDeathQuotePatch` 仍整段注释，已由本补丁替代

多人投票（`AncientMultiplayerVotePatch`）：

- 只对 `ChallengeEncounter != null` 的 `TouhouAncientBase` 生效
- 全员挑战 → 原版；无人挑战 → 各拿各的遗物；混合 → 挂起改票
- 哨兵 `optionIndex = 15`（只有 4 位，不能用 `uint.MaxValue`）
- `GenerateInitialOptions` 用 `new Rng(Owner!, Id)` 让各玩家遗物池不同
- `IsPerPlayerResolution` 时跳过随机选择动画
- 多人给挑战选项加 `TOUHOUANCIENTS-CHALLENGE_COOP` HoverTip；`Owner != null` 才附加

### 7.2 挑战 BGM

`EncounterModel.CustomBgm` **不能**传 `res://` mp3。用 `EncounterBgm` + `AutoModAudio("res://debug_audio")`。原版 FMOD 用 `FmodAudio.SetBusMute("bus:/master/music", true/false)` 静音（与音量独立，不要 `SetBusVolume(0)`，也不要快照/回写总线音量）。mp3 跟 `SettingsSave.VolumeBgm`（开播 `LinearToDb`，滑块经 BaseLib postfix `ModAudio.UpdateVolumes`），走 Godot Master 总线，不受 FMOD mute 影响。子类重写 `BgmFileName`。默认战斗开始就播；`AutoStartBgm => false` 时开场只 mute 原版，由 `EncounterBgm.Start(file, fadeInSeconds)` 手动开始（淡入走 BaseLib `AudioStreamPlayer.FadeIn`）。辉夜在「五道难题」释放后淡入 2 秒，曲名也等到此时才显示。曲名走 encounters 本地化 `{Id.Entry}.bgm`，UI 场景 `res://scenes/ui/bgm_name_display.tscn`。循环看 `.import` 的 `loop=true`。`FmodAudio` 已 Obsolete，用 `#pragma warning disable CS0618`。

### 7.3 多人开局配置同步

BaseLib `SimpleModConfig` 各端本地文件不同步。仿 RitsuLib `RunSavedData`：本机设置只作提交源，开局写成局内数据 `AncientRunSavedData`，随原版开局包的 **字节包尾** 带到客户端（不打 `LobbyBeginRunMessage` 这个 struct 的 Serialize/Deserialize）。`ForcedAncientSyncPatch`：

- 局内字段 `ForcedAncient_2_Run` / `ForcedAncient_3_Run` / `BannedMask_Run`，必须 `[ConfigIgnore]`
- Prefix `RunManager.SetUpNewSingleplayer`：单人 `CommitFromLocalConfig`（清上一局联机残留）
- Prefix `ENetHost.SendMessageToClient` / `ENetClient.SendMessageToHost`（以及 Steam 对应方法）：首字节为 `LobbyBeginRunMessage` 时在 `length` 后追加 26 字节 trailer（页脚 `1SAT`，从包尾往前搜，可与其它 Mod trailer 共存）。不要 patch `NetMessageBus.SerializeMessage<T>`（Harmony 对 struct 泛型 + out 会 `InvalidProgramException`）
- Postfix `NetMessageBus.TryDeserializeMessage`：客户端 Apply 主机数据；本地设置文件不改
- Prefix `RunManager.GenerateRooms`：尚未提交则用本机设置（单人兜底；客户端已 Apply 则跳过）
- 禁用位序必须与 `GetBanBit` / `BuildBannedMask` 一致：0=Nonupeipe, 1=Vakuu, 2=Tanx, 3=Orobas, 4=Pael, 5=Tezcatara, 6=Darv, 7=Reimu, 8=Sanae, 9=Marisa, 10=Satori, 11=Tewi, 12=Seija, 13=Medicine, 14=Nina, 15=Remilia, 16=Tenshi, 17=Yuyuko, 18=Kaguya, 19=Junko, 20=Yuuma, 21=Yorigami, 22=Mamizou（类已注释，位已预留）, 23=Neow（原版涅奥，仅第一幕）, 24=DoremySweet（哆来咪·苏伊特，仅第一幕）。掩码仍是 `ulong`，`AncientRunSavedData` 的 8 字节 trailer 长度不变。

### 7.4 卡牌施加回合内 Power（独白 / 未名妖魔）

`PowerCmd.Apply<T>` 后给 Power 的 DynamicVars 赋值。`BeforeCardPlayed` 记录当前牌，`AfterCardPlayed` 与上一张比颜色。`PowerInstanceType.Instanced`。`AfterSideTurnEnd` 移除并回滚。参考 `NamelessYoukaiPower`。

#### Power 多人按施放者分实例

- 默认 `PowerInstanceType.None`：同一目标共享单个实例，多玩家施放时层数叠在一起、`Applier` 只记**第一个**施放者（`PowerCmd.Apply` 仅新建时 `power.Applier = applier`，后续叠加只走 `ModifyAmount`）。若逻辑按 `Applier` 判定，多人会失效（如怨仇 `YuanChouPower`）。
- 需按玩家分别计算：重写 `public override PowerInstanceType InstanceType => PowerInstanceType.InstancedPerApplier;`（`MegaCrit.Sts2.Core.Entities.Powers`）。叠加时会 `target.GetPowerInstances(Id).FirstOrDefault(p => p.Applier == applier)`，每个施放者各自图标与层数。参考 `YuanChouPower`。
- 带来源的本地化：`description`/`smartDescription` 用 `[gold]{Applier}[/gold]` 指名（如「对[gold]{Applier}[/gold]造成的伤害降低…」）；他人视角用 `.remoteDescription`（如「由于[gold]{Applier}[/gold]的怨仇…」，参考原版夹击 `FLANKING_POWER.remoteDescription`），同样支持 `{Amount}`。三套语言文件需同时维护。

### 7.6 怪物偷牌（SwipePower 模式）

`IWillReturnItPower`：`InstanceType.Instanced` + `StackType.Single`，每张被偷牌一个实例。归还时 `GetPowerInstances<T>()`。动画：场景 `%StolenCardPos`，`NCard.Create` 挂到 Marker2D，`LocalContext.IsMine`。归还 `NCard.FindOnTable(card)?.QueueFreeSafely()`。

位移只 Tween `Visuals.GetCurrentBody()`，记录并恢复 `bodyOrigin`（魔理沙 body 初始不是 0）。携带物挂到 body 下并按 scale 反算。特效 `GD.Load<PackedScene>` 挂 `CombatVfxContainer`。震屏 `NGame.Instance?.ScreenShake(...)`。极限火花场景当前在 `res://images/sprite/marisa/masterspark.tscn`。

紫苑厄运字符：场景 `res://images/sprite/shion/shion_negative_burst.tscn`。字符是同一张图集 `shot_negative_001.png`（256×256）的 4 个 128×128 区域（2×2）。根节点挂 `scripts/Vfx/NShionNegativeBurstVfx.cs`（一次性爆发，`_Ready` 自动播放，播完 `this.QueueFreeSafely()` 自删）。通过 `NShionNegativeBurstVfx.Create(origin, count, scatterRadius)` 创建，内部动态设置 `GpuParticles2D.Amount`（总粒子数）和 `ParticleProcessMaterial.InitialVelocityMin/Max`（散射初速度，通过 `particles.ProcessMaterial as ParticleProcessMaterial` 访问），挂 `CombatVfxContainer`。**每颗粒子随机一个字符（混合出现）同样走图集动画随机帧**（`CanvasItemMaterial` 2×2 + `anim_offset_min=0` + `anim_offset_max=1` + `anim_speed=0`）。厄运播撒、雁过拔毛命中后在玩家 `VfxSpawnPosition` 生成；绝对输家分两波大量播撒。

女苑财富字符：场景 `res://images/sprite/joon/joon_wealth_burst.tscn`。字符是同一张图集 `shot_wealth0000.png`（256×256）的 4 个 128×128 区域（2×2）。根节点挂 `scripts/Vfx/NJoonWealthBurstVfx.cs`（持续发射型，`Start()` 发射 / `Stop()` 停止并延迟自删）。通过 `NJoonWealthBurstVfx.Create(pos)` + `AddChild` + `Start()` 使用，挂 `BackCombatVfxContainer`（角色身后层）。**每颗粒子随机显示一个字符（混合出现）通过纯配置实现**：单个 `GPUParticles2D`，纹理用整张图集，`CanvasItemMaterial.particles_animation=true` + `particles_anim_h_frames=2` + `particles_anim_v_frames=2` + `particles_anim_loop=false`，`ParticleProcessMaterial.anim_offset_min=0` + `anim_offset_max=1`（每颗粒子随机起始帧）+ `anim_speed_min/max=0`（不播放动画，固定随机帧）。

粒子图集动画模式（参考原版 `vfx_sandy_impact` / `vfx_thought_bubble`）：必须用 `GPUParticles2D`（原版图集动画特效都用它，`CPUParticles2D` 对 `process_material` 的 anim 参数支持有限）。运动参数（gravity / velocity / spread / scale / color_ramp / anim_*）全部放 `ParticleProcessMaterial`，节点上只有 `amount` / `texture` / `material` / `process_material` / `emitting` / `one_shot`。scale 用 `scale_min/max` + `scale_curve`（`CurveTexture`），color 用 `color_ramp`（`GradientTexture1D`），与 `CPUParticles2D` 的 `scale_amount_*` / 节点平铺属性不同。GPU 粒子动态改参数：`Amount` 直接设节点属性，初速度等 material 参数通过 `((ParticleProcessMaterial)node.ProcessMaterial).InitialVelocityMin/Max` 设置（参考原版 `NThinSliceVfx`）。

自管 VFX 脚本模式（参考原版 `NBigSlashImpactVfx`）：`partial class ... : Node2D` + `const ScenePath` + 静态 `Create()`（走 `PreloadManager.Cache.GetScene(ScenePath).Instantiate<T>()`，比 `GD.Load` 静态缓存更贴近原版，未预注册路径会 fallback 即时加载并记 `_missedCacheAssets`）+ `_Ready` 里 `TaskHelper.RunSafely(PlaySequence())` 自播自删。注意：粒子 `Lifetime` 是 `double`，`Mathf.Max` 需 `(float)` 强转；扩展方法 `QueueFreeSafely` 无接收者调用会 CS0103，需写 `this.QueueFreeSafely()`。子节点收集需在 `_Ready` 后（`Create` 时 `GetChildren()` 为空），参数先存字段、`_Ready` 里再配置。VFX 脚本随机用 `GD.Randi()` 纯随机（不占用游戏 `Rng` 随机数流）。

魔理沙星星弹幕：场景 `res://images/sprite/marisa/marisa_stellar_stars.tscn`，脚本 `scripts/Vfx/NMarisaStellarStarsVfx.cs`（`Create(origin, starCount)` 一次性齐射自删）。**高速直线飞行粒子**：`ParticleProcessMaterial.direction = Vector3(-1,0,0)`（发射朝向）+ `spread` 小角度（如 8°）+ `initial_velocity_min/max = 2000~2600`（超高速）；**粒子自身旋转**用 `angular_velocity_min/max`（如 ±1440°/s）+ `angle_min/max = -180~180`（初始朝向随机），旋转不需要额外贴图帧；`scale_curve`（CurveTexture 线性衰减）让星星飞行中缩小、`color_ramp`（GradientTexture1D 末段透明）淡出。怪物端：`4 + (int)(GD.Randi() % 5u)` 生成 4~8 数量（GD.Randi 纯随机不占游戏 Rng 流），`creatureNode.VfxSpawnPosition` 为发射原点，挂 `CombatVfxContainer`。

魔理沙瓶子抛射：场景 `res://images/sprite/marisa/marisa_bottle.tscn`，脚本 `scripts/Vfx/NMarisaBottleVfx.cs`。**抛物线 + 持续旋转的节点型飞行物**（参考原版 `NItemThrowVfx` 手写飞行循环而非 GPU 粒子）：`Sprite2D`（Bottle）负责旋转表现（`_bottleSprite.RotationDegrees = t * TotalSpinDegrees` 全程转过固定总角度），GPUParticles2D（Trail，`emitting=false` + `amount` + `one_shot=false` + 短 `lifetime`）作拖尾。飞行循环 `TaskHelper.RunSafely(Fly())`：`while (elapsed < FlightTime)` 内 `float t = elapsed/FlightTime`，**水平匀速 + 垂直正弦弧线** `GlobalPosition = source.Lerp(target, t) - Vector2.Up * (Mathf.Sin(t * Mathf.Pi) * ArcHeight)`（弧顶高 ArcHeight），用 `GlobalPosition` 赋值避免容器原点偏移影响；计时用 `float delta = await this.AwaitProcessFrame()`（`MegaCrit.Sts2.Core.Nodes.GodotExtensions`，返回真实帧间隔，不能用 `GetProcessDeltaTime()`——VFX 节点没开 `_Process` 会返回 0 卡死）。到达落点后 `_trail?.SetEmitting(false)` 停拖尾并触发 `Arrived` 事件（调用方播放命中特效），`_cts`（CancellationTokenSource）在 `_ExitTree` 取消防泄漏。**攻击结算后精确销毁**：怪物端把 `bottleVfx` 存引用，`await DamageCmd.Attack(...)` 完成后 `bottleVfx.QueueFreeSafely()`；命中特效 `NKinPriestGrenadeVfx.Create(target)` 独立挂到玩家 `GetVfxContainer()` 不受瓶子销毁影响（不要把命中特效做成瓶子的子节点）。飞行起点用 `creatureNode.VfxSpawnPosition`、落点取 `targetNode.VfxSpawnPosition`（多人取最左侧玩家 `GlobalPosition.X` 最小）。

卡片/Power 播放自管 VFX：`NCombatRoom.Instance?.GetCreatureNode(creature).VfxSpawnPosition` 获取单位特效出生点（玩家/敌人通用）；持续型（女苑 `NJoonWealthBurstVfx`）用 `Create(pos)` + `AddChild` + `PlayForSeconds(秒)`（内部 Start 后定时 Stop 自删），短暂"背后浮现"挂 `BackCombatVfxContainer`（角色身后层），命中类挂 `CombatVfxContainer`；一次性爆发（紫苑 `NShionNegativeBurstVfx`）用 `Create(pos, count, scatterRadius)` + `AddChild`（`_Ready` 自动播放自删）。Power 的 `BeforeSideTurnEnd` 里可遍历 `CombatState.HittableEnemies` 对每个敌人播一次（不要放进施加 buff 的循环里，避免重复）。

#### 伤害转移（ModifyUnblockedDamageTarget）

原版 `InterceptPower`（拦截）绑定玩家 `Player.NetId`，**怪物不可用**。给怪物用的伤害转移用 `ModifyUnblockedDamageTarget`（原版 `DieForYouPower` 模式）：

```csharp
public override Creature ModifyUnblockedDamageTarget(Creature target, decimal amount, ValueProp props, Creature? dealer)
{
    if (target != base.Owner) return target;          // 只拦截对持有者的攻击
    if (base.Owner.IsDead) return target;
    if (!props.IsPoweredAttack()) return target;      // 仅攻击牌伤害（毒/灾厄不转移）
    if (被转移目标 == null || 被转移目标.IsDead) return target;
    return 被转移目标;
}
```

- 持续时间：`AfterSideTurnStart(CombatSide side, ...)` 中按侧移除。施放发生在敌人回合 → 当次 `Enemy` 侧 `AfterSideTurnStart` 已过，因此在 `side == CombatSide.Enemy` 时 `PowerCmd.Remove(this)` 正好是"下一个敌人回合开始"移除（持续 1 个完整回合）。参考 `GuardingPower`
- 注意 §5.8：`participants` 只含当前行动方，敌人侧的 Power 在玩家回合时 Owner 不在 participants 里，勿用 `participants.Contains(Owner)` 判断

#### 动态意图（StatusIntent 层数）

`StatusIntent(int count)` 的 `CardCount` 是只读的，但 `GetIntentLabel` / `GetIntentDescription` 是 `virtual`。层数动态变化的意图可继承 `StatusIntent`，在显示时重新读取层数：

```csharp
public sealed class LingLingPoisonIntent : StatusIntent
{
    public LingLingPoisonIntent() : base(1) { }
    public override LocString GetIntentLabel(IEnumerable<Creature> targets, Creature owner)
    {
        LocString label = IntentLabelFormat;
        label.Add("CardCount", GetCurrentCount(owner));
        return label;
    }
    // GetIntentDescription 同理，先 base.GetIntentDescription 再 Add
}
```

参考 `DreamNatureIntent`（继承 `MultiAttackIntent` 重写 `DamageCalc`）同模式。
