## 工作协议

> 执行修改前，**必须先向用户说明打算做什么，获得用户同意后再动手**。不得在未告知用户的情况下直接修改代码。
>
> **不准擅自回答用户从未提出的问题**：只回应用户明确提出的请求，不自问自答，不解释用户没问的东西。
>
> 以上两条为硬性约束，违反即视为错误行为。
>
> **严禁操作 Git**：绝对禁止在未经用户明确允许的情况下执行任何 git 操作，包括但不限于 `git reset`、`git checkout`、`git stash`、`git add`、`git commit`、`git push`、`git merge`、`git rebase`。不可操作暂存区或任何涉及 git 历史、索引的行为。此禁令优先级最高。

## 1. 目录结构

仓库根即 Godot 工程。C# 源码在 `scripts/`，本地化在 `TouhouAncients/localization/`，Godot 资源在 `images/`、`scenes/`、`shaders/`、`debug_audio/`。

```
Sts2-TouhouAncients/
├── scripts/
│   ├── Entry.cs                         # Mod 入口：Harmony.PatchAll、EncounterBgm、挑战奖励 Hook
│   ├── TouhouAncientsConfig.cs          # SimpleModConfig：强制/禁用 Ancient、运行期同步字段
│   ├── AncientSpeakerProfile.cs         # 多说话者立绘/气泡配置（建议日后挪到 ancients/）
│   ├── AncientSpeakerRegistry.cs
│   ├── EncounterBgm.cs                  # 挑战战斗 mp3 BGM（建议日后挪到 encounters/）
│   ├── ancients/                        # 先古之民，命名空间目前是 TouhouAncients.Scripts
│   ├── relics/{角色}/                   # 遗物，按角色分子目录
│   ├── cards/                           # 卡牌（平铺）
│   ├── Enchantment/                     # 附魔（平铺）
│   ├── powers/                          # Power（平铺）
│   ├── potions/                         # 药水
│   ├── Afflictions/                     # 侵蚀
│   ├── monsters/                        # 挑战怪物
│   ├── encounters/                      # 挑战遭遇
│   ├── Patches/                         # 跨系统 Harmony 补丁
│   ├── CmdUtils/                        # 路径检查、自定义命令
│   └── keywords/                        # 自定义 CardKeyword（命名空间却是 cardTags）
├── TouhouAncients/localization/{zhs,eng,jpn}/
├── images/                              # 图标、卡肖像、立绘、精灵
├── scenes/                              # 事件背景、怪物视觉、遭遇、UI
├── shaders/
├── debug_audio/                         # 挑战战斗 BGM（mp3）
├── docs/
├── TouhouAncients.csproj
├── TouhouAncients.json
└── project.godot
```

## 2. 命名与命名空间

### 2.1 当前实际命名空间（写代码必须跟这个）

C# 命名空间**不要求**与文件夹大小写一致。本仓库现状：

| `scripts/relics/**` | `TouhouAncients.Scripts.relics` | 基类 `TouhouAncientRelics` 的 namespace 被注释，落在全局命名空间 |

## 4. 内容类型开发规范

### 4.1 遗物

```csharp
[Pool(typeof(SharedRelicPool))]
public class Xxx : TouhouAncientRelics
{
    // 拾起：HasUponPickupEffect + AfterObtained
    // 战斗 Hook：直接重写虚方法
    // 多人：每个 Hook 检查 player != base.Owner（或等价 Owner 判断）
}
```

图标由基类按类名小写解析。休息处触发参考原版 `EternalFeather`：`AfterRoomEntered` + `room is RestSiteRoom`。

地图路线/节点标记（参照原版 `FurCoat`，参考实现 `Mamizou/DragonVeinVessel`）：

- `AfterObtained` 记录 `[SavedProperty] int ...ActIndex`（拾起时的幕），并用 `new Rng(Owner, Id)`（`MegaCrit.Sts2.Core.Random`）确定性随机，不污染主线随机
- `point.AddQuest(this)`（`MegaCrit.Sts2.Core.Map`）在节点上打标记，地图会显示小图标（`NMapPoint` 的 `Quests`）
- 坐标存入 `[SavedProperty] int[] ...CoordCols / ...CoordRows` + `bool ...CoordsSet`，读档/地图重生成时在 `ModifyGeneratedMapLate` 里 `map.GetPoint(coord).AddQuest(this)` 恢复
- 判定当前节点是否被标记：`RunState.CurrentMapPoint.coord` 与保存坐标比对（`MapCoord` 为 struct，可用 `==`/`Contains`）
- `MapPoint.Equals` 是 private（类外是引用比较），比较节点请用 `coord`

### 4.2 附魔

继承 `TouhouAncientEnchantmentModel`。可重写 `CanEnchantCardType`、`CanEnchant`、`OnEnchant`、`OnPlay`。

仅 Attack：`CanEnchantCardType(CardType cardType) => cardType == CardType.Attack`。  
排除 X 费：`card.EnergyCost.CostsX` / `card.HasStarCostX`。  
进入弃牌堆：`card.Pile?.Type == PileType.Discard`，并用 `oldPileType != PileType.Play` 排除正常打出。

从 `ModelDb` 牌池（`GetUnlockedCards` 等）筛候选时，返回的是 **canonical 模板**，不要调 `CanEnchant`。`CardModel.Owner` 会 `AssertMutable()`；其他模组给 `CanEnchant` 打的 Harmony 补丁也可能读 `Owner`，从而 `CanonicalModelException`。池子过滤只用模板上安全的字段（`CanEnchantCardType`、`CanonicalStarCost`、`HasStarCostX`、`Tags`、`CanBeGeneratedInCombat` 等）。`CardFactory.GetDistinctForCombat` 生成带 Owner 的战斗实例后，再对那张可变卡调 `CanEnchant`。

附魔会进战斗 Hook 监听器，可重写 `AfterDamageGiven`、`BeforeDamageReceived` 等全局 Hook。独有 Hook：`OnPlay`、`AfterCardPlayed`、`BeforeFlush`、`AfterCardChangedPiles`、`BeforeCardRemoved`。

无 `[SavedProperty]` 的附魔不必在 `Entry.cs` 注册。

一次性效果用 `base.Status = EnchantmentStatus.Disabled`（需 `MegaCrit.Sts2.Core.Entities.Enchantments`），不要自己做 `_hasTriggered`。

多人同步：**反射枚举（如 `ModelDb.AllAbstractModelSubtypes`）的顺序依赖程序集/类型加载顺序，联机各端不保证一致**。若用它构造候选列表再做 `UnstableShuffle(rng)`（结果依赖列表初始顺序），即使 Rng 流同步，各端也会随机到不同结果。必须在构建缓存时按 `ModelId` 确定性排序：`list.OrderBy(e => e.Id.ToString(), StringComparer.Ordinal).ToList()`（原版 `ModelDb` 亦用 `orderby ... Id.Entry`）。参考 `Yumeiro.cs` 的 `AllEnchantments`。

### 4.3 卡牌

- 继承 `TouhouAncientCards`（`abstract`）
- **具体类必须有 `public` 无参构造函数**，链到 `base(energyCost, type, rarity, targetType, shouldShowInCardLibrary)`
- 基类无参构造器目前是注释掉的，不要依赖它
- 常量放类顶部 `private const`
- `[Pool(typeof(EventCardPool))]` 需要 `using BaseLib.Utils;` 与 `using MegaCrit.Sts2.Core.Models.CardPools;`
- 无需在 `Entry.cs` 注册
- `OnUpgrade` 里用 `base.DynamicVars["Key"].UpgradeValueBy(...)`，不要改 Canonical 默认值字段

```csharp
[Pool(typeof(EventCardPool))]
public class ExampleCard : TouhouAncientCards
{
    private const int energyCost = 1;
    private const CardType type = CardType.Skill;
    private const CardRarity rarity = CardRarity.Ancient;
    private const TargetType targetType = TargetType.Self;
    private const bool shouldShowInCardLibrary = true;

    protected override IEnumerable<DynamicVar> CanonicalVars =>
    [
        new DynamicVar("Damage", 8)
    ];

    public ExampleCard() : base(energyCost, type, rarity, targetType, shouldShowInCardLibrary) { }

    protected override async Task OnPlay(PlayerChoiceContext choiceContext, CardPlay cardPlay) { }

    protected override void OnUpgrade()
    {
        base.DynamicVars["Damage"].UpgradeValueBy(3m);
    }
}
```

| Hook / 成员 | 说明 |
|-------------|------|
| `OnPlay` | 打出效果 |
| `OnUpgrade` | 升级改 DynamicVars |
| `GetResultPileType` | 弃牌去向；回手返回 `PileType.Hand` |
| `GetResultPileTypeForCardPlay` | Quest/能力打出后移出战斗用 `PileType.None` |
| `CanPlay` / `IsPlayable` | 打出限制。**新增**限制优先覆写 `IsPlayable`；破除诅咒/灼伤禁打才用 Harmony Patch `CanPlay` |
| `CanonicalKeywords` | 固有/保留/虚无等 |
| `ExtraHoverTips` | 额外悬停 |
| `BeforeFlush` | 手牌检测阶段改费用 |

费用：`EnergyCost.AddThisTurn(n)`；`SetThisTurn` / `SetThisCombat`。  
辉星：`SetStarCostThisCombat(0)` / `SetStarCostThisTurn(0)` / `SetStarCostUntilPlayed(0)`。  
重放：`card.BaseReplayCount++`；实际次数 `GetEnchantedReplayCount() + 1`。

目标：`None` / `Self` / `SingleEnemy` / `AllEnemies` / `AnyCreature` / `AnyEnemy`。  
类型：`Attack` / `Skill` / `Power` / `Curse` / `Quest`。  
稀有度常用 `CardRarity.Ancient` 或 `CardRarity.Quest`。

### 4.6 `[SavedProperty]`

- 只能标在**自动属性**上，不能标字段

- 仅 `[Pool]`、无 SavedProperty 的类型不注册
- `Entry.cs` 里目前相关调用都被注释掉了；若读档丢状态，先检查是否漏注册

### 4.6.1 怪物演出（灵梦灵符参考）

帧动画怪物做"技能演出 + 场景子节点动画"的参考实现：

- **视觉辅助脚本**：新建继承 `NCreatureVisuals` 的类（如 `scripts/Vfx/HakureiReimuVisuals.cs`）挂在 `creature_visuals/{怪物}.tscn` 根节点，`[Export]` 场景子节点引用（如 `AmuletRoot`），在 `_Ready` 中 `base._Ready()` 后缓存子节点（`GetNodeOrNull<AnimatedSprite2D>`）。怪物侧用 `base.Creature.GetCreatureNode()?.Visuals as HakureiReimuVisuals` 获取。
- **运行时建逐帧动画**：`new SpriteFrames()` + `AtlasTexture { Atlas, Region }` + `AddFrame("default", atlas)`，`SetAnimationSpeed` / `SetAnimationLoop` 控制播放；`AnimatedSprite2D` 没有 `Loop` 属性，必须用 `SpriteFrames.SetAnimationLoop`。
- **切换动画保持当前帧**：`AnimatedSprite2D.Animation` 切换会重置帧，先记录 `amulet.Frame`，切完 `Mathf.Min(当前帧, 新动画帧数-1)` 恢复。
- **位移演出**：`CreateBodyMoveTween(body)`（基类提供，死后自动锁回原位）+ `TweenProperty(body, "position", ...)`；子节点（灵符）直接 `CreateTween().TweenProperty(amulet, "global_position", ...)`，用 `AwaitFinished`（`MegaCrit.Sts2.Core.Nodes.GodotExtensions`）等待完成。
- **禁止受击动画**：重写 `ShouldPlayHurtAnimation => !_isAnimating`，演出开始时置位、结束后复位。
- **坐标系**：`creature_visuals` 根（NCreatureVisuals）与 `NCreature` 原点一致（`Visuals.Position = Vector2.Zero`），场景内 Marker2D（CenterPos/灵符目标）的 `GlobalPosition` 与 `creatureNode.VfxSpawnPosition` 同坐标系，可直接互算。
- **坑**：在继承 `NCreatureVisuals` 的脚本类里 `AddChildSafely`/`QueueFreeSafely`（`MegaCrit.Sts2.Core.Helpers.GodotTreeExtensions`）可能报 CS0103（Godot 源生成器上下文问题），改用 `AddChild`/`QueueFree` 原始 API。

### 5.8 AfterSideTurnStart 的 `participants`

`participants` **只包含当前回合行动的一方**，不是全场。敌人回合时玩家不在列表里。玩家侧遗物不要用 `participants.Contains(Owner.Creature)` 判断自己在不在场，改用 `side == Owner.Creature.Side`。曾因此导致 `DanmukuGhost` 失效。参考 `TwinSoulPower`。

### 5.9 Harmony 补丁要点

`harmony.PatchAll()` **只处理类上带 `[HarmonyPatch]` 的类型**。方法上还要有 `[HarmonyPostfix]` / `[HarmonyPrefix]` 等；光写 `[HarmonyPatch(...)]` 且方法名带 Postfix **不会**自动当 Postfix。参考 `NamelessYoukaiGlowPatch`。

指定卡牌可打出（破除 Unplayable）：Patch `CardModel.CanPlay`。`CurseBreakerQi` 对诅咒；`HinezumiNoKawagoromo` 对 `Burn`。

手牌红蓝流光：Postfix `CardModel.ShouldGlowGold` getter，再 Postfix `NHandCardHolder.UpdateCard` 换材质。shader：`res://shaders/nameless_youkai_flow.gdshader`。必须同步 `NCardHighlight` 私有字段 `_shaderMaterial`。

### 5.10 未名妖魔：手牌变化

`CardSelectCmd.FromHand`（MinSelect=0）。替换牌：`ModelDb.AllCharacterCardPools` 里同稀有度，`card.CardScope.CreateCard`，`CardCmd.Transform`。原卡已升级则 `CardCmd.Upgrade(replacement)`。

### 5.11 弃牌堆捞牌（SilenceDoll）

`AfterCardChangedPiles` 追踪进弃牌的牌；`AfterSideTurnStart` 用 `CardSelectCmd.FromSimpleGrid` 捞回手并 `AddKeyword(Retain)`；打出后若原本没有保留则 `RemoveKeyword`。战斗期数据，开战/结束清空，无需 SavedProperty。

### 5.12 回合奇偶

`combatState.RoundNumber % 2`。参考 `StageDevice`。

### 5.13 死亡预防

`ShouldDieLate` 返回 `false` 阻止死亡，再 `AfterPreventingDeath` 里治疗/扣最大生命。参考 `SoulButterfly`、`KonshiiNoKusuri`。

怪物死后只留尸体：不要把死掉的 `Creature` 留在敌人列表里（`PrepareForNextTurn`/`TakeTurn` 仍会跑）。可让 `ShouldCreatureBeRemovedFromCombatAfterDeath` 暂时 `false`，在自己的 `AfterDeath` 末尾 `CombatManager.RemoveCreature` + `combatState.RemoveCreature(creature, unattach: false)`，不要调用 `NCombatRoom.RemoveCreatureNode()` 直到要播 `NMonsterDeathVfx`。参考依神姐妹怪物。出招中途死亡时用 `unattach: true`，让原版 `PerformMove` 收尾的 `RemoveCreature` 因 `CombatState == null` 直接返回，避免二次移除。

帧动画怪物没有 Spine `attack_target_bone`，冲锋只能挪 `GetCurrentBody()`。`TouhouAncientMonsterBase.BeforeDeath` 会停位移 Tween、把身体拉回原位并播 `die`；死后 `PlayAnimation` / hurt 只允许 `die`。死后仍需播其它动画的怪物重写 `ShouldKeepAnimatingWhileDead`（紫苑双生）。位移用 `CreateBodyMoveTween` / `SetBodyPosition`。

## 6. 注意事项

### 6.1 多人

每个会改状态的 Hook 检查所有权（`player != base.Owner` 或 `card.Owner`）。参考 Nina 遗物 `Yishixingqile`、`Yiyandingzhen`。动画用 `LocalContext.IsMine(card)` / `LocalContext.IsMe(player)`。

### 6.2 脚本扫描

`abstract` 类不会被 Godot 脚本扫描器实例化。具体卡牌/遗物必须可被 `Activator.CreateInstance` 构造。

### 6.3 本地化名称匹配（替代 CardTag）

关键词放 `relics.json`，`LocString.GetFormattedText().Split(',')`，再对 `card.TitleLocString` 做 `Contains`。

### 6.4 MerchantEntry

`list.UnstableShuffle(rng).Take(N)`。商店刷新相关：`SuspiciousToken` + `MerchantRefreshEntry` + `NMerchantRefreshSlot`。

## 7. 大型专题

### 7.1 Ancient 挑战战斗

基类 `TouhouAncientBase` 已内置挑战选项。子类重写：

```csharp
public override SomeEncounter? ChallengeEncounter => ModelDb.Encounter<SomeEncounter>();
```

要点：

- 选项追加在 `GenerateInitialOptions` / `AllPossibleOptions`；子类自定义选项应重写 `GetAncientOptions()`，不要绕开基类
- 若重写 `GenerateInitialOptions()`，必须 `base.GenerateInitialOptions()`，否则挑战胜利遗物奖励为空
- 进入战斗：`EnterCombatWithoutExitingEvent(encounter, rewards, shouldResumeAfterCombat: false)`，传入 **canonical** Encounter（v0.110.1+）
- 挑战是终点：不回事件页；`ShouldGiveRewards => true`；`TouhouAncientEncounter.TryModifyRewards` 只保留 `CombatRoom.ExtraRewards`
- Encounter 默认 `ShouldReceiveCombatHooks => false`，所以 `Entry.Init` 用 `ModHelper.SubscribeForRunStateHooks` 把当前 `TouhouAncientEncounter` 注册进 RunState Hook
- `shouldResumeAfterCombat: false` 使事件不完成，避免 `EventRoom.OnEventStateChanged` 自动存档把奖励弄丢
- 每个玩家事件实例只收集 **本玩家** `_generatedRelicOptions`，不要遍历全员合集再合并（会变成人数倍）
- 回血：`ChallengeRewardPatch` Patch `Hook.AfterCombatVictory`，且 `LocalContext.IsMe(player)`
- 读档恢复跳过重复全回血：`AncientChallengeRestorePatch` 在 `isRestoringRoomStackBase` 时 `MarkPreFinished()`
- `IsChallenge` 用置位-复位，避免污染 canonical
- 挑战按钮图标：`AncientDialoguePortraitPatch` 里 Patch `NEventOptionButton._Ready`；用 `RunHistoryIcon` 不要直接加载 path；宽图 `ResetIconSize`；识别靠 `TextKey.EndsWith(".fight")`，角色专属标题不要改 textKey
- 挑战选项标题：默认 `{AncientId}.fight.title`。角色彩蛋键为 `{AncientId}.fight.{token}.title`，当 `Character.Id.Entry` 包含该 token（忽略大小写）时启用，更长 token 优先。例如妹红 ID 含 `MOKOU` 时用 `fight.mokou.title`。之后只加本地化即可扩展，不必改代码。匹配逻辑在 `CharacterLocVariant`
- 挑战选项描述：`TOUHOUANCIENTS.fight.description`
- 遭遇失败文本：默认 `{EncounterId}.loss`。角色彩蛋键为 `{EncounterId}.loss.{token}`（同样用 `CharacterLocVariant`）。`GetLossMessageFor` 不是虚方法，由 `EncounterLossMessagePatch` Postfix。例如妹红打辉夜用 `HOURAISAN_KAGUYA_ENCOUNTER.loss.mokou`
- 挑战死亡会先被记成事件死亡（`Rooms.First()` 仍是 Ancient 事件）。`EncounterLossMessagePatch` 在 `CreateRunHistoryEntry` 后把 `KilledByEncounter` 改成该地图点最后一场 `TouhouAncientEncounter`，死亡引言才会走 `GetLossMessageFor`。`TouhouAncientEncounter.cs` 里旧的 `TouhouAncientEncounterDeathQuotePatch` 仍整段注释，已由本补丁替代

多人投票（`AncientMultiplayerVotePatch`）：

- 只对 `ChallengeEncounter != null` 的 `TouhouAncientBase` 生效
- 全员挑战 → 原版；无人挑战 → 各拿各的遗物；混合 → 挂起改票
- 哨兵 `optionIndex = 15`（只有 4 位，不能用 `uint.MaxValue`）
- `GenerateInitialOptions` 用 `new Rng(Owner!, Id)` 让各玩家遗物池不同
- `IsPerPlayerResolution` 时跳过随机选择动画
- 多人给挑战选项加 `TOUHOUANCIENTS-CHALLENGE_COOP` HoverTip；`Owner != null` 才附加

### 7.2 挑战 BGM

`EncounterModel.CustomBgm` **不能**传 `res://` mp3。用 `EncounterBgm` + `AutoModAudio("res://debug_audio")`。原版 FMOD 用 `FmodAudio.SetBusMute("bus:/master/music", true/false)` 静音（与音量独立，不要 `SetBusVolume(0)`，也不要快照/回写总线音量）。mp3 跟 `SettingsSave.VolumeBgm`（开播 `LinearToDb`，滑块经 BaseLib postfix `ModAudio.UpdateVolumes`），走 Godot Master 总线，不受 FMOD mute 影响。子类重写 `BgmFileName`。默认战斗开始就播；`AutoStartBgm => false` 时开场只 mute 原版，由 `EncounterBgm.Start(file, fadeInSeconds)` 手动开始（淡入走 BaseLib `AudioStreamPlayer.FadeIn`）。辉夜在「五道难题」释放后淡入 2 秒，曲名也等到此时才显示。曲名走 encounters 本地化 `{Id.Entry}.bgm`，UI 场景 `res://scenes/ui/bgm_name_display.tscn`。循环看 `.import` 的 `loop=true`。`FmodAudio` 已 Obsolete，用 `#pragma warning disable CS0618`。

### 7.3 多人开局配置同步

BaseLib `SimpleModConfig` 各端本地文件不同步。`ForcedAncientSyncPatch`：

- 运行期字段 `ForcedAncient_2_Run` / `ForcedAncient_3_Run` / `BannedMask_Run`，必须 `[ConfigIgnore]`
- Prefix `StartRunLobby.BeginRunForAllPlayers` 拷贝本地配置
- Postfix `LobbyBeginRunMessage.Serialize/Deserialize` 追加 magic `0x54414631` + 字段
- 禁用位序必须与 `GetBanBit` / `BuildBannedMask` 一致：0=Nonupeipe, 1=Vakuu, 2=Tanx, 3=Orobas, 4=Pael, 5=Tezcatara, 6=Darv, 7=Reimu, 8=Sanae, 9=Marisa, 10=Satori, 11=Tewi, 12=Seija, 13=Medicine, 14=Nina, 15=Remilia, 16=Tenshi, 17=Yuyuko, 18=Kaguya, 19=Junko, 20=Yuuma, 21=Yorigami, 22=Mamizou（类已注释，位已预留）
- 旧版消息 try-catch 降级；不要在 Postfix 声明 struct `__instance`

### 7.4 卡牌施加回合内 Power（独白 / 未名妖魔）

`PowerCmd.Apply<T>` 后给 Power 的 DynamicVars 赋值。`BeforeCardPlayed` 记录当前牌，`AfterCardPlayed` 与上一张比颜色。`PowerInstanceType.Instanced`。`AfterSideTurnEnd` 移除并回滚。参考 `NamelessYoukaiPower`。

#### Power 多人按施放者分实例

- 默认 `PowerInstanceType.None`：同一目标共享单个实例，多玩家施放时层数叠在一起、`Applier` 只记**第一个**施放者（`PowerCmd.Apply` 仅新建时 `power.Applier = applier`，后续叠加只走 `ModifyAmount`）。若逻辑按 `Applier` 判定，多人会失效（如怨仇 `YuanChouPower`）。
- 需按玩家分别计算：重写 `public override PowerInstanceType InstanceType => PowerInstanceType.InstancedPerApplier;`（`MegaCrit.Sts2.Core.Entities.Powers`）。叠加时会 `target.GetPowerInstances(Id).FirstOrDefault(p => p.Applier == applier)`，每个施放者各自图标与层数。参考 `YuanChouPower`。
- 带来源的本地化：`description`/`smartDescription` 用 `[gold]{Applier}[/gold]` 指名（如「对[gold]{Applier}[/gold]造成的伤害降低…」）；他人视角用 `.remoteDescription`（如「由于[gold]{Applier}[/gold]的怨仇…」，参考原版夹击 `FLANKING_POWER.remoteDescription`），同样支持 `{Amount}`。三套语言文件需同时维护。

### 7.5 怪物随机外观

重写 `CreateCustomVisuals()`，用 `base.Rng`（不要 `GD.Randf`）。每个外观单独 tscn，各自把 Sprite 锚点烘在贴图底部。参考 `FantasyMushroomMonster`。

### 7.6 怪物偷牌（SwipePower 模式）

`IWillReturnItPower`：`InstanceType.Instanced` + `StackType.Single`，每张被偷牌一个实例。归还时 `GetPowerInstances<T>()`。动画：场景 `%StolenCardPos`，`NCard.Create` 挂到 Marker2D，`LocalContext.IsMine`。归还 `NCard.FindOnTable(card)?.QueueFreeSafely()`。

位移只 Tween `Visuals.GetCurrentBody()`，记录并恢复 `bodyOrigin`（魔理沙 body 初始不是 0）。携带物挂到 body 下并按 scale 反算。特效 `GD.Load<PackedScene>` 挂 `CombatVfxContainer`。震屏 `NGame.Instance?.ScreenShake(...)`。极限火花场景当前在 `res://images/sprite/marisa/masterspark.tscn`。

紫苑厄运字符：场景 `res://images/sprite/shion/shion_negative_burst.tscn`。字符是同一张图集 `shot_negative_001.png`（256×256）的 4 个 128×128 区域（2×2）。根节点挂 `scripts/Vfx/NShionNegativeBurstVfx.cs`（一次性爆发，`_Ready` 自动播放，播完 `this.QueueFreeSafely()` 自删）。通过 `NShionNegativeBurstVfx.Create(origin, count, scatterRadius)` 创建，内部动态设置 `GpuParticles2D.Amount`（总粒子数）和 `ParticleProcessMaterial.InitialVelocityMin/Max`（散射初速度，通过 `particles.ProcessMaterial as ParticleProcessMaterial` 访问），挂 `CombatVfxContainer`。**每颗粒子随机一个字符（混合出现）同样走图集动画随机帧**（`CanvasItemMaterial` 2×2 + `anim_offset_min=0` + `anim_offset_max=1` + `anim_speed=0`）。厄运播撒、雁过拔毛命中后在玩家 `VfxSpawnPosition` 生成；绝对输家分两波大量播撒。

女苑财富字符：场景 `res://images/sprite/joon/joon_wealth_burst.tscn`。字符是同一张图集 `shot_wealth0000.png`（256×256）的 4 个 128×128 区域（2×2）。根节点挂 `scripts/Vfx/NJoonWealthBurstVfx.cs`（持续发射型，`Start()` 发射 / `Stop()` 停止并延迟自删）。通过 `NJoonWealthBurstVfx.Create(pos)` + `AddChild` + `Start()` 使用，挂 `BackCombatVfxContainer`（角色身后层）。**每颗粒子随机显示一个字符（混合出现）通过纯配置实现**：单个 `GPUParticles2D`，纹理用整张图集，`CanvasItemMaterial.particles_animation=true` + `particles_anim_h_frames=2` + `particles_anim_v_frames=2` + `particles_anim_loop=false`，`ParticleProcessMaterial.anim_offset_min=0` + `anim_offset_max=1`（每颗粒子随机起始帧）+ `anim_speed_min/max=0`（不播放动画，固定随机帧）。

粒子图集动画模式（参考原版 `vfx_sandy_impact` / `vfx_thought_bubble`）：必须用 `GPUParticles2D`（原版图集动画特效都用它，`CPUParticles2D` 对 `process_material` 的 anim 参数支持有限）。运动参数（gravity / velocity / spread / scale / color_ramp / anim_*）全部放 `ParticleProcessMaterial`，节点上只有 `amount` / `texture` / `material` / `process_material` / `emitting` / `one_shot`。scale 用 `scale_min/max` + `scale_curve`（`CurveTexture`），color 用 `color_ramp`（`GradientTexture1D`），与 `CPUParticles2D` 的 `scale_amount_*` / 节点平铺属性不同。GPU 粒子动态改参数：`Amount` 直接设节点属性，初速度等 material 参数通过 `((ParticleProcessMaterial)node.ProcessMaterial).InitialVelocityMin/Max` 设置（参考原版 `NThinSliceVfx`）。

自管 VFX 脚本模式（参考原版 `NBigSlashImpactVfx`）：`partial class ... : Node2D` + `const ScenePath` + 静态 `Create()`（走 `PreloadManager.Cache.GetScene(ScenePath).Instantiate<T>()`，比 `GD.Load` 静态缓存更贴近原版，未预注册路径会 fallback 即时加载并记 `_missedCacheAssets`）+ `_Ready` 里 `TaskHelper.RunSafely(PlaySequence())` 自播自删。注意：粒子 `Lifetime` 是 `double`，`Mathf.Max` 需 `(float)` 强转；扩展方法 `QueueFreeSafely` 无接收者调用会 CS0103，需写 `this.QueueFreeSafely()`。子节点收集需在 `_Ready` 后（`Create` 时 `GetChildren()` 为空），参数先存字段、`_Ready` 里再配置。VFX 脚本随机用 `GD.Randi()` 纯随机（不占用游戏 `Rng` 随机数流）。

卡片/Power 播放自管 VFX：`NCombatRoom.Instance?.GetCreatureNode(creature).VfxSpawnPosition` 获取单位特效出生点（玩家/敌人通用）；持续型（女苑 `NJoonWealthBurstVfx`）用 `Create(pos)` + `AddChild` + `PlayForSeconds(秒)`（内部 Start 后定时 Stop 自删），短暂"背后浮现"挂 `BackCombatVfxContainer`（角色身后层），命中类挂 `CombatVfxContainer`；一次性爆发（紫苑 `NShionNegativeBurstVfx`）用 `Create(pos, count, scatterRadius)` + `AddChild`（`_Ready` 自动播放自删）。Power 的 `BeforeSideTurnEnd` 里可遍历 `CombatState.HittableEnemies` 对每个敌人播一次（不要放进施加 buff 的循环里，避免重复）。

### 7.12 怪物随从战斗（梅蒂欣 × 铃铃）

多怪物挑战战斗 = Boss + 随从双槽位。参考 `MedicineMelancholyEncounter`：

```csharp
public override IReadOnlyList<string> Slots => ["medicine", "lingling"]; // 随从在左侧
protected override IReadOnlyList<(MonsterModel, string?)> GenerateMonsters() =>
[
    (ModelDb.Monster<MedicineMelancholyMonster>().ToMutable(), "medicine"),
    (ModelDb.Monster<LingLingMonster>().ToMutable(), "lingling")
];
```

- 随从天生幻象：`AfterAddedToRoom` 中 `PowerCmd.Apply<IllusionPower>`（自动附带 `MinionPower`，参考原版 `EyeWithTeeth`/`Parafright`）
- 跨怪物找队友：`creature.CombatState.GetTeammatesOf(creature).FirstOrDefault(c => c is { Monster: XxxMonster, IsDead: false })`（`GetTeammatesOf` 含自身）
- 修改敌方 Power 层数：`PowerCmd.ModifyAmount(choiceContext, power, offset, applier, null)`（有 Hook 联动与显示刷新，优于 Remove + 重 Apply）
- 向玩家弃牌堆塞牌：`CardPileCmd.AddToCombatAndPreview<Toxic>(targets, PileType.Discard, count, null, CardPilePosition.Random)`（参考原版 `Myte`、本项目 `FungalPower`）

#### 伤害转移（ModifyUnblockedDamageTarget）

原版 `InterceptPower`（拦截）绑定玩家 `Player.NetId`，**怪物不可用**。给怪物用的伤害转移用 `ModifyUnblockedDamageTarget`（原版 `DieForYouPower` 模式）：

```csharp
public override Creature ModifyUnblockedDamageTarget(Creature target, decimal amount, ValueProp props, Creature? dealer)
{
    if (target != base.Owner) return target;          // 只拦截对持有者的攻击
    if (base.Owner.IsDead) return target;
    if (!props.IsPoweredAttack()) return target;      // 仅攻击牌伤害（毒/灾厄不转移）
    if (被转移目标 == null || 被转移目标.IsDead) return target;
    return 被转移目标;
}
```

- 持续时间：`AfterSideTurnStart(CombatSide side, ...)` 中按侧移除。施放发生在敌人回合 → 当次 `Enemy` 侧 `AfterSideTurnStart` 已过，因此在 `side == CombatSide.Enemy` 时 `PowerCmd.Remove(this)` 正好是"下一个敌人回合开始"移除（持续 1 个完整回合）。参考 `GuardingPower`
- 注意 §5.8：`participants` 只含当前行动方，敌人侧的 Power 在玩家回合时 Owner 不在 participants 里，勿用 `participants.Contains(Owner)` 判断

#### 动态意图（StatusIntent 层数）

`StatusIntent(int count)` 的 `CardCount` 是只读的，但 `GetIntentLabel` / `GetIntentDescription` 是 `virtual`。层数动态变化的意图可继承 `StatusIntent`，在显示时重新读取层数：

```csharp
public sealed class LingLingPoisonIntent : StatusIntent
{
    public LingLingPoisonIntent() : base(1) { }
    public override LocString GetIntentLabel(IEnumerable<Creature> targets, Creature owner)
    {
        LocString label = IntentLabelFormat;
        label.Add("CardCount", GetCurrentCount(owner));
        return label;
    }
    // GetIntentDescription 同理，先 base.GetIntentDescription 再 Add
}
```

参考 `DreamNatureIntent`（继承 `MultiAttackIntent` 重写 `DamageCalc`）同模式。
