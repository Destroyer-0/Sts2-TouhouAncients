## 工作协议

> 执行修改前，**必须先向用户说明打算做什么，获得用户同意后再动手**。不得在未告知用户的情况下直接修改代码。
>
> **不准擅自回答用户从未提出的问题**：只回应用户明确提出的请求，不自问自答，不解释用户没问的东西。
>
> 以上两条为硬性约束，违反即视为错误行为。
>
> **严禁操作 Git**：绝对禁止在未经用户明确允许的情况下执行任何 git 操作，包括但不限于 `git reset`、`git checkout`、`git stash`、`git add`、`git commit`、`git push`、`git merge`、`git rebase`。不可操作暂存区或任何涉及 git 历史、索引的行为。此禁令优先级最高。

### 2.4 添加新先古之民注意事项
每次添加**新的 Ancient 角色**时，必须在 `scripts/TouhouAncientsConfig.cs` 中：
1. **强制节 (`ForcedAncients`)** — 将角色名添加到 `ForcedAncientOption` 枚举，并在 `IsAncientForced` switch 中添加对应条目
2. 在 `localization/zhs/settings_ui.json` 中添加对应的配置标题本地化键
3. 在 Ancient 类中重写 `IsValidForAct`（仅保留 `act.ActNumber()` 逻辑）和 `ShouldForceSpawn`（返回 Force）

> **禁用选项全自动处理：**
> - `BanAncientPatch` 在 `Initialize()` 时扫描所有 `AncientEventModel` 子类（排除 Neow），自动创建禁用选项
> - `SetupConfigUI` 重写动态生成"禁用先古之民"分区下的每个复选框
> - 持久化通过 `BannedAncientData`（逗号分隔的 Type.FullName）由 SimpleModConfig 自动保存/加载
> - **添加新 Ancient 时，无需在 Config 中加任何 Ban 相关代码**
> 
> **现有规则**：每个 Ancient 仍需要手写 `IsValidForAct`（仅保留 Act 限制逻辑）和 `ShouldForceSpawn`。原手写的 `BanXxx` 检查已被 Patch 统一拦截替代。

### 2.5 附魔属性规范

```csharp
public class Xxx : CustomEnchantmentModel  // 来自 BaseLib.Abstracts
{
    // 覆盖 CanEnchantCardType → 限制可附魔卡牌类型
    // 覆盖 CanEnchant(CardModel card) → 更精细的限制（如排除X费牌）
    // 覆盖 OnEnchant → 应用关键字/属性修改
    // 覆盖 OnPlay → 打出时效果 (可选)
}
```

`CanEnchant(CardModel card)` 在 `CanEnchantCardType` 之后调用，用于检查完整卡牌对象：

```csharp
public override bool CanEnchant(CardModel card)
{
    // 排除能量费用为X的牌（CostsX = 能量X费）
    if (card.EnergyCost.CostsX) return false;
    // 排除星数费用为X的牌（HasStarCostX = 星数X费）
    if (card.HasStarCostX) return false;
    return true;
}
```
> 判断 X 费牌的两个属性：`card.EnergyCost.CostsX`（能量X费）和 `card.HasStarCostX`（星数X费）。

### 2.7 卡牌开发规范

#### 卡牌基类约定
- 所有 Mod 卡牌继承 `TouhouAncientCards`（`scripts/cards/TouhouAncientCards.cs`），该类继承 `CustomCardModel`
- `TouhouAncientCards` 标记为 `abstract`，避免被 `ScriptManagerBridge` 直接实例化
- 基类已提供无参构造器（`protected`），满足 Godot 反射扫描需求；子类无需额外处理
- 肖像路径自动解析：`res://sprite/cards/{类名}.png`
- 命名空间一律：`TouhouAncients.Scripts.cards`
- `[Pool(typeof(EventCardPool))]` → 卡牌出现池子；不加则不会出现在任何奖励中

#### 构造函数规范
- 必须提供**无参构造函数**：`public Xxx() : base(energyCost, type, rarity, targetType, shouldShowInCardLibrary)`
- `base()` 的参数在类顶部定义为 `private const`，方便查阅
- 示例：`SatoriEye.cs` — `0`费技能，`CardRarity.Ancient`，目标自身
- `shouldShowInCardLibrary` 控制是否在图鉴中显示

#### 无参构造器说明
`TouhouAncientCards` 标记为 `abstract` → `ScriptManagerBridge` 会跳过抽象基类，不会尝试实例化。
但**具体卡牌子类**（如 `SatoriEye`）**必须**提供 `public` 无参构造器，链向基类带参：
```csharp
public SatoriEye() : base(energyCost, type, rarity, targetType, shouldShowInCardLibrary) { }
```
这是为了：
1. `ScriptManagerBridge.LookupScriptsInAssembly` 通过 `Activator.CreateInstance` 扫描程序集时实例化具体卡牌类型
2. Godot 序列化/反序列化也需要无参构造器

> 基类 `abstract` → 不会被扫描；子类 `public 无参` → 被扫描 + 链入基类带参构造器

#### CanonicalVars 运行时变量
| 变量类型 | 用途 | 示例 |
|---------|------|------|
| `DynamicVar` | 通用数值变量 | `new DynamicVar("Damage", 8)` |
| `EnergyVar` | 能量相关 | `new EnergyVar(2)` → 动态能量增减 |
| `BlockVar` | 格挡相关 | `new BlockVar(5)` |
| `CardsVar` | 卡牌数量 | `new CardsVar(3)` |

- 变量通过 `base.DynamicVars["Key"].BaseValue` 读写
- 升级用 `base.DynamicVars["Key"].UpgradeValueBy(value)` 而非修改字段

#### 卡牌 Hook 汇总

| Hook | 说明 | 示例 |
|------|------|------|
| `OnPlay` | 打出时效果 | `SatoriEye` — 预见5 + 本回合耗能+2 |
| `OnUpgrade` | 升级时数值变化 | `SatoriEye` — 能量消耗减少1 |
| `GetResultPileType` | 自定义弃牌去向 | `SatoriEye` — 返回手牌而非弃牌堆 |
| `CanonicalKeywords` | 卡牌关键字 | `SatoriEye` — `[CardKeyword.Retain]` |

public override bool TryModifyCardRewardOptions(Player player, List<CardCreationResult> options, CardCreationOptions creationOptions)

    if (base.Owner != player) return false;

    var customCards = new List<CardModel>
    {
        ModelDb.Card<SomeCard>()
    };

    var servantOptions = new CardCreationOptions(customCards, CardCreationSource.Other, CardRarityOddsType.Uniform)
        .WithFlags(CardCreationFlags.NoModifyHooks | CardCreationFlags.NoCardPoolModifications);

    var created = CardFactory.CreateForReward(base.Owner, 1, servantOptions).FirstOrDefault();

    result.ModifyCard(created.Card, this);
    options.Add(result);
    return true;
}

### 4.13 Ancient 挑战战斗（进入 Encounter 战斗 + 胜利奖励）

基类 `scripts/ancients/TouhouAncientBase.cs` 已内置"挑战"选项支持，参照原版 `PUNCH_OFF`（选项与本地化）和 `BattlewornDummy`（战斗后 resume 结算）实现。

**启用方式：** 在子类中重写 `ChallengeEncounter` 属性返回 Encounter（默认 null 不启用）：

```csharp
public override YorigamiSistersEncounter? ChallengeEncounter => ModelDb.Encounter<YorigamiSistersEncounter>();
```

启用后自动生效：
- 选项列表末尾追加"挑战"选项（`GenerateInitialOptions` 与 `AllPossibleOptions` 都会追加）
- 点击挑战 → `EnterCombatWithoutExitingEvent(encounter.ToMutable(), rewards, shouldResumeAfterCombat: false)` 进入战斗
- **挑战战斗是终点**（参照 PUNCH_OFF / DenseVegetation）：胜利后走标准战斗奖励流程，在战斗结束时弹出奖励页（各玩家随机池的遗物），不返回事件页；随后进入地图。回血（已损失生命值的 50%）由 `ChallengeVictoryHealPatch`（Hook.AfterCombatVictory，战斗胜利存档之前）处理

**关键点：**
- 战斗事件必须 `IsShared == true`（BaseLib 要求 "Required for combat events"），基类已自动处理：`IsShared => ChallengeEncounter != null`
- 子类自定义选项列表时应重写 `GetAncientOptions()`（而非 `AllPossibleOptions`），否则挑战选项不会追加
- 若子类重写 `GenerateInitialOptions()`，需调用 `base.GenerateInitialOptions()`（用于填充挑战胜利的遗物奖励缓存），否则挑战胜利后遗物奖励为空
- **走标准战斗奖励流程（`ShouldGiveRewards => true`）+ 原生 ModifyRewards 钩子剔除默认奖励**：`TouhouAncientEncounter.TryModifyRewards` 在奖励生成时只保留 `CombatRoom.ExtraRewards[player]`、移除其余默认奖励（金币/卡牌/药水）。因 Encounter 默认不在 Hook 监听者遍历里（`ShouldReceiveCombatHooks => false`），在 `Entry.Init` 用 **`ModHelper.SubscribeForRunStateHooks`**（游戏原生 mod 扩展点）把当前挑战 Encounter 注册进 RunState Hook 监听者；按类型判断（`runState.CurrentRoom` 是 CombatRoom 且 Encounter 是 `TouhouAncientEncounter`），正常/读档奖励流程都生效、读档重建后依然有效，无需持久化 IsChallenge。`StartChallenge` 把各玩家随机池的遗物作为 **extraRewards 传入 `EnterCombatWithoutExitingEvent`**（存入 `CombatRoom.ExtraRewards`）
- **读档可靠重弹奖励**：`shouldResumeAfterCombat: false` 使事件永不"完成"，从而**不会触发 `EventRoom.OnEventStateChanged` 的自动存档**（旧方案奖励丢失的根源）。战斗胜利时只有 `SaveRun(combatRoom)`（`CombatRoom.ExtraRewards` 随存档持久化）；读档后 `StartPreFinishedCombat` → `ShouldGiveRewards = true` → `OfferRoomEndRewards` → 奖励页可靠地重新弹出（游戏原生处理，不依赖事件字段）
- `StartChallenge` 为**所有玩家**收集各自随机池的遗物（遍历 `EventSynchronizer.Events` 各实例的 `_generatedRelicOptions`；各端实例一致 → 各端 `ExtraRewards` 内容一致，多人奖励同步正常）
- **回血在战斗胜利存档之前**（`ChallengeVictoryHealPatch`，Patch `Hook.AfterCombatVictory`）：`Hook.AfterCombatVictory` 在战斗胜利的 `SaveRun` 之前触发，回血写入存档 → 读档后不丢血也不会重复回血。各端只给本地玩家治疗（`if (LocalContext.IsMe(player))`），避免多人重复治疗
- **进入先古全回血保留 + 读档恢复跳过重复回血**（`AncientChallengeRestorePatch`，Patch `EventRoom.EnterInternal`）：进入先古之民房间的全回血（原版 `AncientEventModel.BeforeEventStarted`）是既定机制，**保留**。但挑战战斗是终点、事件不完成，读档恢复时原版 `RunManager.EnterMapPointInternal` 会用 `new EventRoom(...)`（默认非 pre-finished）重建父事件房间并以 `isPreFinished=false` 重新 `BeginEvent`，导致 `BeforeEventStarted` 再次全回血——把挑战后写入存档的真实生命覆盖回"挑战前"。补丁在重建父事件房间（`isRestoringRoomStackBase=true`）时对启用挑战的 `TouhouAncientBase` 调用 `EventRoom.MarkPreFinished()`，使 `BeginEvent` 以 `isPreFinished=true` 调用（原版 isPreFinished 时本就不回血），从而保留挑战后的真实生命；正常进入先古房间（`isRestoringRoomStackBase=false`）不受影响，全回血保留。参考 `scripts/Patches/AncientChallengeRestorePatch.cs`
- `IsChallenge` 用于 `ChallengeVictoryHealPatch` 识别挑战战斗（仅战斗进行中的内存态，读档后 AfterCombatVictory 不触发、无需持久化）
- 本地化键（参照 PUNCH_OFF，位于 `ancients.json`）：
  - `{AncientId}.pages.INITIAL.options.CHALLENGE.title` / `.description` — 挑战按钮
  - `{AncientId}.pages.CHALLENGE.description` — 战斗胜利后的结束文本（方法二下事件页不再显示，该键保留备用）
- 奖励遗物在 `StartChallenge` 中用 `RelicReward(canonicalRelic.ToMutable(), player)` 构建，每个玩家独立实例（从 canonical 克隆），避免共享同一 mutable 实例
- `AllPossibleOptions` 中的挑战选项 `Relic == null`，遗物图鉴（`o.Relic?.CanonicalInstance` + `OfType`）与 `BottomlessStomach` 等引用方会自动过滤

**挑战选项图标（Harmony Patch `NEventOptionButton._Ready`）：**
- `EventOption` 类本身没有图标属性；原版 Ancient 按钮只在 `Option.Relic != null` 时显示场景中的 `%RelicIcon`（60×60，默认隐藏），因此挑战选项（Relic == null）没有图标
- 解决方案：在 `scripts/Patches/AncientDialoguePortraitPatch.cs` 中 Patch `NEventOptionButton._Ready`，当事件是 `TouhouAncientBase`、`ChallengeEncounter != null`、选项 textKey 以 `.fight` 结尾时，手动显示 `%RelicIcon`
- 图标复用 Ancient 自身的 `RunHistoryIcon` / `RunHistoryIconOutline` 属性（**不要**直接加载 `CustomRunHistoryIconPath`）——这两个属性已被 BaseLib `RoomIconPathPatch` 与项目 `RunHistoryIcon_Patch` 处理，多说话者（如依神姐妹）会经过 `MergeAllVariants` 横向合并为拓宽宽度后的样式
- 宽图需配合 `ResetIconSize(icon, tex)`（保持高度 60、按纹理宽高比调整宽度）调整 `%RelicIcon` 的 `CustomMinimumSize`，否则会被压进 60×60 框内
- 判断挑战选项：`option.Relic == null && option.TextKey.EndsWith(".fight")`（普通遗物选项 Relic 非空，天然排除）
- 注意：`%RelicIcon` 的子节点 `%Outline`（半透明黑色描边）从 icon 节点下查找：`icon.GetNode<TextureRect>("%Outline")`

**多人模式投票结算（Harmony Patch `scripts/Patches/AncientMultiplayerVotePatch.cs`）：**
- 背景：原版共享事件在全员投票后由房主**随机抽一个选项并对全员执行同一选项**（`EventSynchronizer.ChooseSharedEventOption` → `_multiplayerOptionSelectionRng.NextItem(_playerVotes)`），导致：遗物选项被统一成同一行、全员必须选一样才能继续
- 本补丁只对 `ChallengeEncounter != null` 的 `TouhouAncientBase` 生效，其他 Ancient 完全不受影响。结算分为三种情况：
  1. **全员投挑战** → 走原版逻辑，全员进入挑战战斗（行为不变）
  2. **无人投挑战** → 按玩家分别结算：每个玩家在自己那份事件实例上执行自己投的遗物（各拿各的，互不同步）
  3. **混合投票**（有人挑战有人遗物）→ 不结算、挂起等待，玩家可改票，直到全员一致（要么全员挑战，要么全员遗物）
- 实现：Patch `EventSynchronizer.ChooseSharedEventOption`（房主侧决策）与 `EventSynchronizer.ChooseOptionForSharedEvent`（全员侧执行）
  - 按玩家分别结算时，房主广播 `SharedEventOptionChosenMessage`，用哨兵值 `optionIndex = 15` 表示"按玩家分别结算"；各端用本地已知的 `_playerVotes` 逐玩家调用私有方法 `ChooseOptionForEvent(player, index)`（执行选项 + 记录历史）
  - **哨兵值必须落在 4 位内**：`SharedEventOptionChosenMessage.optionIndex` 序列化用 `WriteUInt(optionIndex, 4)`（只写低 4 位，0~15）。若哨兵用 `uint.MaxValue`，客户端读回来会被截断成 15 → 检测不到哨兵 → 走原版 `ChooseOptionForSharedEvent(15)` 选项越界抛异常，客机卡死（房主本地直接结算不受影响）。故哨兵取 15（真实选项索引 0~3 远小于 15）
  - 混合等待时房主不发任何消息，事件停留在投票页；共享事件中玩家在结算前可反复点选改票（`NEventRoom.OptionButtonClicked` 对共享事件不清理选项），"合作事件"提示（`SHARED_EVENT_INFO`）+ 各选项上的投票图标就是协调手段
- **每个玩家独立抽取遗物池**：`GenerateInitialOptions` 用 `new Rng(Owner!, Id)`（按"运行种子 + 玩家槽位 + 事件ID"派生，对齐非共享事件的种子规则）替代原共享事件的事件级 `Rng`（不含玩家槽位 → 全员同池）。因此多人时各玩家看到/掉落各自的随机遗物，挑战胜利奖励（`Resume` 中 `_generatedRelicOptions`）也是那名玩家自己的随机池；所有客户端按同一规则生成（跨端一致、可同步）
- 注意：各玩家选项集不同，但挑战选项始终在末尾且 textKey 均以 `.fight` 结尾，补丁用 textKey 匹配定位挑战选项索引（避免硬编码索引）
- **按玩家分别结算时跳过"随机选择"动画/音效**：`ResolvePerPlayer` 在执行任何选项前对所有事件实例置位 `TouhouAncientBase.IsPerPlayerResolution = true`；Patch `EventSplitVoteAnimation.TryPlay`（Prefix）检测到该标记时直接返回完成（跳过 `map_split_tick.mp3` 随机选择音效与循环高亮动画），`NEventLayout.BeforeSharedOptionChosen` 的禁用/置灰/确认闪光反馈保留。原因：按玩家结算没有随机抽取，播随机选择动画会误导
- **有人投挑战时的协同提示（HoverTip）**：不需要布局注入。Ancient 布局没有原版的 `%SharedEventLabel` 节点（`SHARED_EVENT_INFO` 只在 default/combat 布局显示），因此在 `TouhouAncientBase.CreateChallengeOption` 里**仅多人模式**（`Owner.RunState.Players.Count > 1`）给挑战选项附加一个 `HoverTip`：`new HoverTip(new LocString("ancients", "TOUHOUANCIENTS-CHALLENGE_COOP"))`，文案为"这是一个合作事件，所有玩家均确认进行挑战后方可进行"。悬停挑战选项时 `NEventOptionButton` 会通过 `NHoverTipSet` 展示（`OnFocus` → `Option.HoverTips`）；单人模式传空数组不附加
  - 注意：`CreateChallengeOption` 会被 `GenerateInitialOptions`（mutable 实例，`Owner` 已设置）与 `AllPossibleOptions`（canonical 实例，`Owner` 为 null）调用，`Owner != null` 判断保证 canonical 下安全返回空 tips

### 4.14 挑战战斗自定义 BGM（AutoModAudio + FMOD 音乐总线静音）

`EncounterModel.CustomBgm` 只接受 FMOD 事件路径（`event:/...`），**不能**传 `res://` 的 mp3 路径——传了会在日志报 `cannot find music path: res://...`，并且 `PlayCustomMusic` 会先把当前 FMOD 音乐停掉，导致战斗期间完全无声。若 mod 只有 mp3 资源，用 BaseLib 的 `AutoModAudio` 手动播放（见 `scripts/EncounterBgm.cs`）：

- 在 `Entry.Init()` 调用 `EncounterBgm.Initialize()`，订阅 `CombatManager.Instance.CombatSetUp` / `CombatEnded`（C# 事件，胜负都会触发 `CombatEnded`）
- 基类：`scripts/encounters/TouhouAncientEncounter.cs`（继承 `CustomEncounterModel`），子类只需重写 `BgmFileName`（位于 `res://debug_audio/` 的文件名，或完整 `res://` 路径；返回 null 表示不播放）——每个 Encounter 的 BGM 各不同
- `CombatSetUp` 时判断 `state.Encounter is TouhouAncientEncounter e && e.BgmFileName != null`，命中则：
  - 记录并静音 FMOD 音乐总线：`FmodAudio.GetBusVolume("bus:/master/music")` / `FmodAudio.SetBusVolume("bus:/master/music", 0f)`——避免与原 act 音乐重叠（mp3 走 Godot Master 总线，不受 FMOD 音乐总线影响）
  - `AutoModAudio.PlayMusic(e.BgmFileName)` 播放（`new AutoModAudio("res://debug_audio")`）
- `CombatEnded` 时停止播放器并恢复音乐总线音量

**要点：**
- **循环**：`AutoModAudio`/`ModAudio` 不会强制循环，循环与否取决于音频导入设置——`debug_audio/TFM-010b_03.mp3.import` 需 `loop=true`（改后需 Godot 重新导入）
- **音量**：`ModAudio`（`SoundType.Music`）自动读取 `SettingsSave.VolumeBgm`（背景音乐音量）与 `VolumeMaster`，并 Patch 了 `VolumeBgm` setter，设置改变时实时更新，无需手动处理
- 音乐播放器通过 `RemoveChild` 归还给 ModAudio 的播放器池（`TreeExited` 自动回收）
- `FmodAudio`（`BaseLib.Utils`）被 BaseLib 标记为 Obsolete，使用时用 `#pragma warning disable CS0618` 抑制警告
- 注意：`ModAudio` 播放的 mod 音乐与原版 FMOD 音乐是两套系统，必须靠静音 FMOD 音乐总线才能"替换"而不是叠加

## 6. 常见注意事项

### 6.1 多人模式
- 每个 Hook 都要检查 `player != base.Owner`
- 参考 `Yishixingqile`, `Yiyandingzhen` 的实现

### 6.2 存档序列化
- `[SavedProperty]` 标记的**属性**会自动持久化
- **必须使用自动属性（auto-property）**，不能标记在字段上：
  ```csharp
  // ✅ 正确：属性
  [SavedProperty] private string TouhouAncients_MyData { get; set; }
  
  // ❌ 错误：字段（BaseLib 会忽略字段上的 [SavedProperty]）
  [SavedProperty] private string _myData;
  ```
- 建议使用 `TouhouAncients_` 前缀避免与其他 Mod 的 SavedProperty 冲突
- Mod 中的类型需在 `Entry.cs` 注册: `SavedPropertiesTypeCache.InjectTypeIntoCache<Type>()`

### 6.3 脚本注册
- `abstract` 类不会被 Godot 脚本扫描器注册
- `TouhouAncientRelics` 是 abstract，不会生成遗物实例
- `TouhouAncientCards` 是 abstract，不会生成卡牌实例

### 6.4 卡牌注册说明
- 卡牌无需在 `Entry.cs` 中手动注册，`ScriptManagerBridge.LookupScriptsInAssembly` 会自动扫描
- `TouhouAncientCards` 必须标记为 `abstract`，否则会因无参构造函数缺失而报错
  `TouhouAncientCards No parameterless constructor defined`
- 具体卡牌类必须有 `public` 无参构造函数调用 `base(energyCost, type, rarity, targetType, shouldShowInCardLibrary)`
- 卡牌使用 `[Pool(typeof(EventCardPool))]` 属性指定出现的池子（如事件、商店等）

### 6.4 附魔的 Hook 生命周期
- 附魔 (`CustomEnchantmentModel`) 继承自 `AbstractModel`
- 战斗中卡牌的附魔会被 `CombatState.IterateHookListeners()` 包含 → **可以接收全局 Hook**
- 可用但**附魔独有的** Hook（对应 `CardModel` 的虚方法）：
  - `OnPlay` — 打出时
  - `AfterCardPlayed` — 打出后
  - `BeforeFlush` — 手牌检测阶段（可用于费用修改）
  - `AfterCardChangedPiles` — 卡牌换牌堆时
  - `BeforeCardRemoved` — 卡牌被移除时
- 可用的**全局** Hook（通过 `AbstractModel` 继承）：
  - `AfterDamageGiven` — 造成伤害后
  - `BeforeDamageReceived` — 受到伤害前
- 参考 `Bloodshed`, `SnakeBiteUpgrade`, `HighQuality`

### 6.5 `[SavedProperty]` 注册规则
- `[SavedProperty]` 标记的**属性**会自动持久化到存档
- **必须使用自动属性（auto-property）**，不能标记在字段上：`[SavedProperty] private string Name { get; set; }`
- 建议的命名格式：`TouhouAncients_{描述}`，避免与其他 Mod 冲突（BaseLib 会 warn 无前缀的 SavedProperty）
- 参考 `HighQuality.cs`（附魔费用减量）：
  ```csharp
  [SavedProperty] private int TouhouAncients_EnergyDelta { get; set; }
  ```
- 参考 `Tribute.cs`（卡牌进度持久化）：
  ```csharp
  [SavedProperty] private int SavedGoldContributed { get; set; }
  ```
- Mod 中的类型需在 `Entry.cs` 的 `Init()` 中注册：
  ```csharp
  SavedPropertiesTypeCache.InjectTypeIntoCache(typeof(HighQuality));
  SavedPropertiesTypeCache.InjectTypeIntoCache(typeof(BrainInAVat));
  ```
  - **遗物**和**附魔**有 `[SavedProperty]` 才需注册
  - 仅 `[Pool]` 属性而无 `[SavedProperty]` 的类型（如 `Miracle` / `Bloodshed` / `Recollection`）→ 不注册
- 适用于**遗物**、**附魔**和**卡牌**的运行时状态持久化

### 6.6 一次性附魔效果：使用 EnchantmentStatus.Disabled

对于只需触发一次的附魔效果（如回忆：首次弃牌自动打出），无需 `_hasTriggered` 私有字段标记。

```csharp
// ❌ 不要这样
private bool _hasTriggered;
// ... if (_hasTriggered) return; _hasTriggered = true;

// ✅ 推荐
base.Status = EnchantmentStatus.Disabled;
```

`EnchantmentStatus.Disabled` 会将附魔标记为停用状态，效果等同于"已消耗"：
- 附魔不再出现在 UI 悬浮提示中
- 后续 `AfterCardChangedPiles`、`OnPlay` 等 Hook **不会再被调用**（因为 `Hook.cs` 的 `IterateHookListeners` 遍历时不会回调）
- 不需要额外字段，读档后也自动保留状态

**注意**: `base.Status` 需要引入 `MegaCrit.Sts2.Core.Entities.Enchantments` 命名空间。
参考 `Recollection` 附魔实现。

### 6.8 死亡预防模式（ShouldDieLate + AfterPreventingDeath）
用于"生命值降至0时触发效果"的遗物：
```csharp
// ShouldDieLate → false 阻止死亡，true 允许死亡
public override bool ShouldDieLate(Creature creature)
{
    if (creature != base.Owner.Creature) return true;
    if (!hasTrigger) return true;  // 无触发物则正常死亡
    return false;                   // 阻止死亡
}

public override async Task AfterPreventingDeath(Creature creature)
{
    Flash();
    await CreatureCmd.Heal(creature, healAmount);
    await CreatureCmd.LoseMaxHp(new ThrowingPlayerChoiceContext(), creature, lossAmount, isFromCard: false);
}
```
参考 `SoulButterfly`、`KonshiiNoKusuri`。

#### 死亡后仅保留尸体视觉

如果怪物死后只需要保留画面表现，不需要继续参与战斗，不要通过假的 `MoveState`
让死亡的 `Creature` 留在敌人列表中。`CombatManager` 会对敌人列表中的所有单位调用
`PrepareForNextTurn()` 和 `TakeTurn()`，不会自动跳过死亡单位，因此只隐藏一次意图并不能阻止
下回合重新生成、播放意图。

需要保留完整尸体和原版死亡风化效果时，可以让
`ShouldCreatureBeRemovedFromCombatAfterDeath` 暂时返回 `false`，隐藏原始 `NCreature` 的意图并
关闭交互。`CombatState.IterateHookListeners()` 会在执行 Hook 前先把监听者复制到独立列表，
因此可以在该怪物自己的 `AfterDeath` 末尾调用 `CombatManager.RemoveCreature(creature)` 和
`combatState.RemoveCreature(creature, unattach: false)`，立即将其从敌人列表注销。
`unattach: false` 会暂时保留 `creature.CombatState`，确保本次死亡流程的后续 Hook 仍能获得
原战斗上下文。不要调用 `NCombatRoom.RemoveCreatureNode()`，从而只保留原始显示节点。

最终需要让尸体消失时，对保留的 `NCreature` 调用原版 `NMonsterDeathVfx.Create(...)`，
将播放任务赋给 `DeathAnimationTask`，再调用 `NCombatRoom.RemoveCreatureNode()`。这样无需复制
`AnimatedSprite2D` 或重新实现淡出参数，气泡定位、节点层级和未来原版特效修改也能继续复用。
参考 `YorigamiJoon` 和 `YorigamiShion`。

### 7.5 弃牌堆追踪 + 捞牌模式（SilenceDoll）

追踪上回合进入弃牌堆的牌，让玩家选择一张回到手牌并附加保留：

```csharp
// ① 追踪进入弃牌堆的牌
private readonly List<CardModel> _currentTurnDiscards = new();
private readonly Dictionary<CardModel, bool> _trackedCards = new();

public override Task BeforeCombatStart()
{
    _currentTurnDiscards.Clear();
    _trackedCards.Clear();
    return Task.CompletedTask;
}

public override async Task AfterCardChangedPiles(CardModel card, PileType oldPileType, AbstractModel? source)
{
    if (card.Owner != base.Owner) return;
    if (card.Pile?.Type == PileType.Discard)
        _currentTurnDiscards.Add(card);
}

// ② 回合开始时捞牌
public override async Task AfterSideTurnStart(CombatSide side, CombatState combatState)
{
    if (side != base.Owner.Creature.Side) return;

    var available = _currentTurnDiscards
        .Where(c => c.Pile?.Type == PileType.Discard && c.Owner == base.Owner)
        .Distinct().ToList();
    _currentTurnDiscards.Clear();
    if (available.Count == 0) return;

    Flash();
    var selected = (await CardSelectCmd.FromSimpleGrid(
        new BlockingPlayerChoiceContext(), available, base.Owner,
        new CardSelectorPrefs("选择一张牌", 1, 1)
    )).FirstOrDefault();
    if (selected == null) return;

    // ③ 检查原本是否有保留
    bool hadRetain = selected.CanonicalKeywords?.Contains(CardKeyword.Retain) ?? false;
    _trackedCards[selected] = hadRetain;
    selected.AddKeyword(CardKeyword.Retain);
    await CardPileCmd.Add(selected, PileType.Hand);
}

// ④ 打出后移除保留（若非原生保留）
public override async Task AfterCardPlayed(PlayerChoiceContext ctx, CardPlay cardPlay)
{
    if (!_trackedCards.TryGetValue(cardPlay.Card, out bool hadRetain)) return;
    if (!hadRetain) cardPlay.Card.RemoveKeyword(CardKeyword.Retain);
    _trackedCards.Remove(cardPlay.Card);
}
```
参考 `SilenceDoll`。
- 仅战斗运行时数据，`BeforeCombatStart`/`AfterCombatEnd` 清空，无需 `[SavedProperty]`

### 7.7 怪物随机外观（多场景各自烘焙锚点）

怪物可通过重写 `CreateCustomVisuals()` 在视觉创建时随机加载不同场景。推荐使用 `base.Rng`（战斗级 RNG，多人端可同步、可复现），不要用 `GD.Randf` 等全局随机。

每个外观单独建一个 tscn，各自把 `Visuals`（Sprite2D）的 `offset.y` 设为「-贴图高度 / 2」，让节点锚点（原点）落在贴图底部（`centered = true` 时）；代码只负责随机选场景：

```csharp
public override NCreatureVisuals? CreateCustomVisuals()
{
    // 随机二选一：备用小蘑菇场景 / 默认大蘑菇场景（战斗 RNG，多人端可同步）
    if (base.Rng.NextBool())
    {
        return NodeFactory<NCreatureVisuals>.CreateFromScene("res://scenes/creature_visuals/FantasyMushroomAlt.tscn");
    }

    return base.CreateCustomVisuals();
}
```

要点：
- `Sprite2D.Offset` 为局部坐标，会随节点 `scale` 一起缩放；`centered = true` 时 `offset.y = -贴图高度 / 2` 即锚点落于贴图底部（mush_big.png 高 64 → -32；mushroom002.png 高 48 → -24）。
- 不同尺寸贴图各建各的场景、各自烘焙锚点，即可严格底部对齐，无需补白图片、无需在代码中计算偏移。
- 视觉创建发生在 `NCreature.Create` 时，此时 `base.Rng` 已由 `CombatState.CreateCreature` 注入。
- 参考 `FantasyMushroom`（大蘑菇 mush_big.png 64×64）/ `FantasyMushroomAlt`（小蘑菇 mushroom002.png 48×48）。

### 7.8 怪物偷牌暂存模式（Instanced Power，仿原版 SwipePower）

每张被偷的牌创建一个独立的能力实例暂存，归还时遍历并移除。参考原版 `SwipePower`（`ThievingHopper`）与本 Mod `IWillReturnItPower`。

```csharp
// 偷牌：每张牌创建并施加一个 Instanced 能力实例
IWillReturnItPower returnPower = (IWillReturnItPower)ModelDb.Power<IWillReturnItPower>().ToMutable();
returnPower.StolenCard = cardToSteal;
await PowerCmd.Apply(new ThrowingPlayerChoiceContext(), returnPower, base.Creature, 1m, base.Creature, null);

// 归还：遍历所有实例，归还牌后移除
List<IWillReturnItPower> returnPowers = base.Creature.GetPowerInstances<IWillReturnItPower>().ToList();
foreach (IWillReturnItPower returnPower in returnPowers)
{
    if (returnPower.StolenCard is not { } card) continue;
    card.HasBeenRemovedFromState = false;
    await CardPileCmd.Add(card, PileType.Hand);
}
foreach (IWillReturnItPower returnPower in returnPowers)
{
    await PowerCmd.Remove(returnPower);
}
```

要点：
- 能力需 `InstanceType.Instanced` + `StackType.Single`，`PowerCmd.Apply` 每次施加都会新建实例（`FindExistingInstanceForStacking` 对 Instanced 恒返回 null）。
- 用 `Creature.GetPowerInstances<T>()` 获取同类型全部实例。
- 每个实例用 `ExtraHoverTips`（`HoverTipFactory.FromCard`）显示被偷的牌。
- 参考 `IWillReturnItPower`、`KirisameMarisaMonster`（逃逸速度 / 极限火花·蓄力）。

### 7.9 怪物偷牌卡牌动画（仿原版 ThievingHopper）

偷牌后让被偷的牌显示在怪物身后（"卡牌从牌堆中飞到身后"的观感）。参考原版 `ThievingHopper.ThieveryMove` 与本 Mod `KirisameMarisaMonster`（逃逸速度）。

### 4.15 卡牌池创建 + 网格选择（参照 SeaGlass / CosmicDecree）

```csharp
// 创建卡牌池选项

var options = CardCreationOptions.ForNonCombatWithUniformOdds(
    new[] { cardPool },          // 卡牌池
    _ => true)                   // 筛选条件（全部）
    .WithFlags(CardCreationFlags.NoRarityModification 
              | CardCreationFlags.NoCardPoolModifications
              | CardCreationFlags.NoUpgradeRoll);

// 生成卡牌
var creationResults = CardFactory.CreateForReward(player, cardCount, options).ToList();

// 升级
foreach (var result in creationResults)
    if (result.Card.IsUpgradable) CardCmd.Upgrade(result.Card);

// 网格多选（min=0 表示可以不选）
var selected = (await CardSelectCmd.FromSimpleGridForRewards(
    new BlockingPlayerChoiceContext(),
    creationResults,
    player,
    new CardSelectorPrefs(promptLocString, minSelect: 0, maxSelect: creationResults.Count)

// 选定牌加入牌组
var addResults = new List<CardPileAddResult>();
foreach (var card in selected)
    addResults.Add(await CardPileCmd.Add(card, PileType.Deck));
CardCmd.PreviewCardPileAdd(addResults, 2f);

### 4.17 Power 动态追踪全场模式（参照 LuckyRabbitPower）

当 buff 需要在生效期间给**所有战斗牌堆**中的目标牌动态附加效果时，使用组合 Hook 多方位捕获：

```csharp
public class MyTrackingPower : PowerModel
{
    public override PowerType Type => PowerType.Buff;
    public override PowerStackType StackType => PowerStackType.Counter;

    // ① Power 被应用/递增时 → 扫描全场已有牌
    public override async Task AfterApplied(Creature? applier, CardModel? cardSource)
    {
        var combatState = base.Owner.Player?.PlayerCombatState;
        if (combatState == null) return;

        var allPiles = new[] { combatState.Hand.Cards, combatState.DrawPile.Cards, combatState.DiscardPile.Cards };
        foreach (var pile in allPiles)
            foreach (var card in pile)
                ApplyEffect(card);
    }

    // ② 抽牌时 → 捕获新入手的牌
    public override async Task AfterCardDrawn(PlayerChoiceContext ctx, CardModel card, bool fromHandDraw)
    {
        if (card.Owner != base.Owner.Player) return;
        ApplyEffect(card);
    }

    // ③ 牌堆间移动时 → 捕获从牌组/外部进入战斗的牌
    public override async Task AfterCardChangedPiles(CardModel card, PileType oldPile, AbstractModel? source)
    {
        if (card.Owner != base.Owner.Player) return;
        if (card.Pile == null || !card.Pile.IsCombatPile) return;
        bool fromOutside = oldPile is PileType.None or PileType.Deck;
        if (fromOutside)
            ApplyEffect(card);
    }

    // ④ 回合结束自动移除
    public override async Task BeforeTurnEnd(PlayerChoiceContext ctx, CombatSide side)
    {
        if (side == base.Owner.Side) await PowerCmd.Remove(this);
    }

    private void ApplyEffect(CardModel card) { /* 根据条件给 card 附加效果 */ }
}
```
