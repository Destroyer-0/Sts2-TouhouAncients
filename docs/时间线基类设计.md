# TouhouAncientTimeline 时间线基类设计

> 目标：为原版「历史节点」（Timeline / Epoch / Story）提供 Mod 侧扩展入口。新增内容只需继承类、准备资源与文案、在 `Entry.Init()` 注册。

## 1. 原版机制基线

| 机制 | 原版实现 | 对 Mod 的影响 |
|---|---|---|
| 节点基类 | `EpochModel`：`Id`、`Era`、`EraPosition`、`StoryId`、`GetTimelineExpansion()`、`QueueUnlocks()` | 基类封装样板 |
| 故事基类 | `StoryModel`：`Id`（protected）、`Epochs` | 章节顺序不能直接手写 |
| 注册 | `EpochModel._epochTypeDictionary`、`_typeToIdDictionary`、`StoryModel._storyTypeDictionary` 均为 `private static` | 必须反射写入 |
| 合法性 | `EpochModel.IsValid` 只认 `_allEpochIds` 缓存 | 不刷新会读档丢节点 |
| 多人 | `ModelIdSerializationCache` 按 `AllEpochIds` 顺序生成 net id 与 hash | 只能追加，不能重排 |
| 布局 | 列 = `Era`（按枚举整数排序），行 = `EraPosition`（0 在列底） | 自定义列选未占用整数 |
| 列名/年份 | `eras` 表 `{slug}.name` / `.year` | slug 由 `NTimelineScreen.GetEraIcon` 返回 |
| 列图标 | `res://images/atlases/era_atlas.sprites/era_{int}.tres` | Mod 可直接给 PNG |
| 槽位图 | `EpochModel.Portrait` → `PackedPortraitPath`（atlas `.tres`） | 无 atlas 需回退 PNG |
| 详情图 | `EpochModel.RealPortrait` → `ResolvedPortraitPath` | 约定 `timeline/epoch_portraits/{id}.png` |
| 显示流程 | `UnlockSlot`（开槽）→ `ObtainEpoch`（获得）→ 点击 `RevealEpoch` | 新装 Mod 需补槽 |
| 发奖 | `QueueUnlocks()` 只在点开已获得节点时调用 | 奖励逻辑放这里 |
| 自动解锁 | `GetRevealableEpochs` 只沿涅奥节点的 `GetTimelineExpansion()` 遍历 | Mod 节点需规则引擎触发 |

## 3. 节点基类

```csharp
public abstract class TouhouAncientTimeline : EpochModel
{
    protected abstract string TimelineId { get; }
    public sealed override string Id => TimelineId;

    public sealed override EpochEra Era => Registry.ResolveEra(GetType());
    public sealed override int EraPosition => Registry.ResolvePosition(GetType());
    public override string? StoryId => Registry.ResolveStoryId(GetType());

    protected virtual string? PortraitPath => null;
    protected virtual string? SlotPortraitPath => null;

    public override EpochModel[] GetTimelineExpansion()
        => Registry.ResolveExpansion(GetType());
}
```

约定：

- `Era`、`EraPosition` 为 `sealed`，位置只能由注册表分配，避免静默重叠。
- `TimelineId` 建议带 `TOUHOUANCIENTS_` 前缀，例如 `TOUHOUANCIENTS_GENSOKYO_A`.
- `QueueUnlocks()` 由子类重写，发奖时调用 `NTimelineScreen.Instance.QueueMiscUnlock(...)` 或原版奖励命令。
- 文案键：`epochs` 表 `{Id}.title` / `.description` / `.unlockInfo` / `.unlockText`。
- 故事标题键：`epochs` 表 `STORY_{StoryId.ToUpperInvariant()}`。

## 4. 故事基类

```csharp
public abstract class TouhouAncientTimelineStory : StoryModel
{
    protected abstract string StoryKey { get; }
    protected sealed override string Id => StringHelper.Slugify(StoryKey);
    public sealed override EpochModel[] Epochs => Registry.ResolveStoryEpochs(GetType());
}
```

`StoryKey` 会 slugify 成 `StoryModel.Id`；节点 `StoryId` 自动取同一个原始 key。

注意：`StoryKey` 用**小写蛇形**（如 `touhou_gensokyo`），不要写成全大写。原版 `StoryModel.Get` 会对 `StoryId` 再执行一次 `Slugify`，全大写字符串会被拆成 `T_O_U_H_O_U...`，导致找不到 Story。

## 5. 时代列

```csharp
TouhouAncientTimelineEra.AppendTo(EpochEra.Seeds1);                 // 追加到原版列
TouhouAncientTimelineEra.Custom(4000, "touhou_gensokyo", iconPath); // 独立列
```

- `AppendTo`：自动扫描 0..127 找该列最小空位。
- `Custom`：整数只用于列排序；不能使用已定义的 `EpochEra` 值（会被拒绝）。传入的 slug 会经 `StringHelper.Slugify` 转成大写。
- 冲突在启动期抛错，不静默覆盖。
- 独立列默认排在相邻原版列右侧；想插在中间就选相邻时代之间的整数。
- 列名/年份：`eras` 表 `{Slug}.name` / `.year`，例如 `TOUHOU_GENSOKYO.name`。
- 列图标优先级：`IconPath` → 最近原版时代图标。

## 6. 注册

### 6.1 显式注册

```csharp
TouhouAncientTimelineRegistry.RegisterStory<GensokyoStory>("touhou_gensokyo");
TouhouAncientTimelineRegistry.RegisterEpoch<GensokyoEpochA>(TouhouAncientTimelineEra.Custom(4000, "touhou_gensokyo"));
TouhouAncientTimelineRegistry.RegisterStoryChapter<GensokyoStory, GensokyoEpochA>(order: 0);
TouhouAncientTimelineRegistry.AddRule<GensokyoEpochA>(
    TouhouTimelineUnlockRule.AfterWinAs("IRONCLAD"));
```

### 6.2 注解注册

```csharp
[TouhouTimelineStory("touhou_gensokyo")]
public sealed class GensokyoStory : TouhouAncientTimelineStory { ... }

[TouhouTimelineEpoch(4000, EraSlug = "touhou_gensokyo", StoryKey = "touhou_gensokyo", ChapterOrder = 0)]
public sealed class GensokyoEpochA : TouhouAncientTimeline { ... }
```

注解先于显式注册扫描；重复类型会跳过并记录日志。

### 6.3 接入点

显式注册必须写在 `Initialize()` **之前**；`Initialize()` 会冻结注册表。

`Entry.Init()` 内、任何模型/存档初始化之前：

```csharp
TouhouAncientTimelineRegistry.Initialize();
```

注册表会：

1. 触发 `EpochModel` / `StoryModel` 静态构造，读取原版字典。
2. 写入 Mod 节点与故事类型。
3. 先登记全部原版节点的 `(Era, EraPosition)`，再分配 Mod 槽位。
4. 刷新 `_allEpochIds`：保留原版顺序，仅追加 Mod Id。
5. 建立章节顺序与展开链（第 N 章揭示后展开第 N+1 章）。

## 7. 头像与列图标

| 用途 | 解析顺序 |
|---|---|
| 槽位 | `SlotPortraitPath` → 原版 atlas（若存在）→ `PortraitPath` → `images/timeline/epoch_portraits/{id小写}.png` |
| 详情 | `PortraitPath` → `images/timeline/epoch_portraits/{id小写}.png` |
| 列图标 | `TouhouAncientTimelineEra.IconPath` → 最近原版时代图标 |

- `PortraitPath` 支持 `res://` 绝对路径，也支持相对 `images/` 的路径。
- 两个 getter 由 Harmony postfix 处理，只作用于 `TouhouAncientTimeline` 实例。
- 列图标与列名由 `NTimelineScreen.GetEraIcon` 前缀补丁处理；`EpochModel.Year` 由后置补丁同步修正。当前游戏版本没有 `EpochModel.EraName`，不要给它写补丁。

## 8. 存档与槽位

- `ProgressSaveManager.LoadProgress` postfix 与 `NTimelineScreen.OnSubmenuOpened` postfix 调用 `EnsureRootSlots()`。
- 只补故事根节点与无故事节点；后续章节由 `GetTimelineExpansion()` 展开，避免剧透。
- 补槽使用 `ProgressState.UnlockSlot(id)`：缺条目时建 `NotObtained`，已有 `ObtainedNoSlot` 时提升为 `Obtained`；不直接操作私有列表。
- 移除 Mod 后，未知 Id 会被原版 `ParseEpochs` 保留到 `_unknownEpochs` 并原样写回。

## 9. 解锁

### 9.1 手动 API

```csharp
TouhouAncientTimelineRegistry.OpenSlot<TEpoch>();
TouhouAncientTimelineRegistry.TryObtain<TEpoch>(player.DiscoveredEpochs);
TouhouAncientTimelineRegistry.Reveal<TEpoch>();
TouhouAncientTimelineRegistry.IsRevealed<TEpoch>();
```

### 9.2 规则引擎

触发点：

- `SaveManager.UpdateProgressWithRunData` postfix：局末规则。
- `SaveManager.UpdateProgressAfterCombatWon` postfix：战斗结束规则。
- `EventModel.BeginEvent` postfix：遭遇先古之民时立即求值。

内置规则：

| 规则 | 数据来源 |
|---|---|
| `AfterRunAs(characterEntry)` | `SerializableRun` + 本机 `SerializablePlayer` |
| `AfterWinAs(characterEntry)` | 同上 + `victory` |
| `AfterVictory()` | `victory` |
| `AfterAscensionWin(level)` | `SerializableRun.Ascension` |
| `AfterRunCount(count, requireVictory)` | `ProgressState.NumberOfRuns` / `Wins` |
| `AfterDefeatEncounter(encounterEntry)` | `CombatRoom.Encounter.Id.Entry` |
| `AfterEliteVictories(count)` | 汇总 `ProgressState.EncounterStats` 中 `RoomType.Elite` 的胜场 |
| `AfterBossVictories(count)` | 同上，`RoomType.Boss` |
| `AfterClearAct(actIndex)` | `CombatRoom.RoomType == Boss` + `RunState.CurrentActIndex` |
| `AfterEncounterAncient<T>()` | `EventModel.BeginEvent` 的 `AncientEventModel` 实例 |
| `Custom(Func<TouhouTimelineUnlockContext, bool>)` | 调用方自定 |

保护：

- `GameMode.AreAchievementsAndEpochsLocked()` 为真时跳过。
- 多人只处理本机账号；`LocalContext.GetMe(run)` 为空时退回 `run.Players` 首个玩家。
- 获得时写入 `DiscoveredEpochs`，保留结算页 `NGainEpochVfx` 反馈；不自动揭示。
- 规则异常只记录日志，不阻断其他规则。

## 10. BaseLib 持久化策略

默认不新增存档，规则全部读原版进度：

- 局数/胜场：`SaveManager.Instance.Progress.NumberOfRuns` / `Wins`；
- 角色胜负：`Progress.GetStatsForCharacter(id)`；
- 精英/Boss 胜场：`Progress.EncounterStats`；
- 进阶等级：`SerializableRun.Ascension`。

仅当后续规则需要原版进度无法表达的计数时：

1. 先探测 `BaseLib.Patches.Saves.ExtendedSaveTypes.IsSaveHolderSupported(typeof(SerializableProgress))`。
2. 支持则用 `ExtendedSaveHandlers<ProgressState, SerializableProgress>.RegisterSave(...)`。
3. 不支持则不引入账号级自定义文件，规则限定为原版数据可表达的集合。
4. 局内临时标记仍可用 `ExtendedSaveHandlers<Player, SerializablePlayer>`（项目已有先例）。

不要用 `[SavedProperty]` 存账号级进度：它属于模型/局内存档，作用域不对。

## 11. 风险

1. 私有字段反射会随游戏版本变动；反射集中在 `TouhouAncientTimelineRegistry`，启动期失败只记录日志。
2. 自定义 `EpochEra` 整数只能决定列顺序，无法插入原版列中间。
3. 多人要求双方 Mod 版本一致（`ModelIdSerializationCache` hash 校验）。
4. 原版槽位图默认走 atlas；只给 PNG 时必须依赖本设计的 postfix。
5. 没有正式节点内容时无法做端到端验证；先做注册自检与编译验证，内容到位后再补运行期验证。

## 12. 验证清单

- `dotnet build TouhouAncients.csproj -t:Compile` 通过。
- 启动日志出现 `Timeline registered: X stories, Y epochs`，无 `Timeline registration failed`。
- 时间线出现自定义列/槽位，读档后节点不消失。
- 触发对应规则后节点变为已获得，点开后 `QueueUnlocks()` 正常执行。
- 多人两端 Mod 版本一致时可正常连接。
