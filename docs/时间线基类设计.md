# TouhouAncientTimeline 时间线设计

> 原版「历史节点」（Timeline / Epoch / Story）的 Mod 扩展入口。新增节点 = 写一个类 + 一行注册 + `epochs.json` 文案。

## 1. 原版机制基线

| 机制 | 原版实现 | 对 Mod 的影响 |
|---|---|---|
| 节点基类 | `EpochModel`：`Id`、`Era`、`EraPosition`、`StoryId`、`GetTimelineExpansion()`、`QueueUnlocks()` | 基类封装样板 |
| 故事基类 | `StoryModel`：`Id`（protected）、`Epochs` | 章节顺序由注册表给 |
| 注册 | `EpochModel._epochTypeDictionary`、`_typeToIdDictionary`、`StoryModel._storyTypeDictionary` 均为 `private static` | 必须反射写入 |
| 合法性 | `EpochModel.IsValid` 只认 `_allEpochIds` | 不刷新会读档丢节点 |
| 多人 | `ModelIdSerializationCache` 按 `_allEpochs` / `AllEpochIds` 生成 net id 与 hash | 只能追加，不能重排 |
| 布局 | 列 = `Era`（按枚举整数排序），行 = `EraPosition`（0 在列底） | 自建列取 Invitation7 之后的整数 |
| 列名/年份 | `eras` 表 `{slug}.name` / `.year` | 自建列没有，需补丁复用门扉 |
| 列图标 | `res://images/atlases/era_atlas.sprites/era_{int}.tres` | 自建列没有，需补丁复用门扉 |
| 槽位图 | `EpochModel.Portrait` → `PackedPortraitPath`（atlas `.tres`） | 无 atlas 需回退 PNG |
| 详情图 | `EpochModel.RealPortrait` → `ResolvedPortraitPath` | 约定 `timeline/epoch_portraits/{id}.png` |
| 显示流程 | `UnlockSlot`（开槽）→ `ObtainEpoch`（获得）→ 点击 `RevealEpoch` | 注册表补槽 + 解锁时获得 |
| 发奖 | `QueueUnlocks()` 只在点开已获得节点时调用 | 奖励逻辑放这里 |

## 2. 文件结构

```text
scripts/Timeline/
├─ TouhouAncientTimeline.cs            // 节点基类、唯一故事、门扉列、解锁方式
├─ TouhouAncientTimelineRegistry.cs    // 注册、布局、槽位、解锁求值
├─ TouhouAncientTimelineContent.cs     // 具体节点 + Register()
└─ TouhouTimelineResetConsoleCmd.cs    // touhou-timeline-reset 控制台命令
scripts/Patches/
└─ TouhouTimelinePatches.cs            // 头像、列图标/年份、补槽、遭遇解锁
```

## 3. 唯一故事

```csharp
public const string Key = "touhou_ancients_story";   // StoryModel.Id = TOUHOU_ANCIENTS_STORY
```

- 本 Mod 全部节点共用 `TouhouAncientStory`，节点 `StoryId` 固定返回该 key。
- 故事标题键：`epochs` 表 `STORY_TOUHOU_ANCIENTS_STORY`（`STORY_` + 大写 Id，**没有** `.title`）。
- **key 必须小写蛇形**：原版会对 `StoryId` 再 `Slugify`，全大写会被拆成 `T_O_U_H_O_U...`，`StoryModel.Get` 直接抛异常。
- 章节顺序 = 按 `(Era, EraPosition)` 从下到上排列，`ChapterIndex` 自动得到。

## 4. 门扉列

```csharp
TouhouAncientTimelineEra.Door(0);  // 紧接原版 Invitation7，对应 2740
TouhouAncientTimelineEra.Door(1);  // 2741
```

- 所有本 Mod 节点都放在自建「门扉」列，名称与年份复用原版 `INVITATION0`：「门扉 / 2,733」。
- 列图标、列名、`EpochModel.Year` 都由补丁改成复用门扉，避免读取不存在的 `era_2740.tres` 与 `eras` 键。
- 列内顺序由 `position` 决定：0 在列底，数字越大越靠上。原版 Invitation7 已占用位置 1，新列从 0 起是空的。
- 同一列同一 `position` 会在启动期抛冲突异常，不会静默重叠。

## 5. 解锁方式

只有三种：

| 写法 | 触发 |
|---|---|
| `TouhouTimelineUnlock.Default` | 开局即获得（`EnsureSlots` 时置为 Obtained） |
| `TouhouTimelineUnlock.AnyTouhouAncient` | 遇到任意东方先古之民 |
| `TouhouTimelineUnlock.Ancient<T>()` | 遇到指定东方先古之民（`T` 继承 `TouhouAncientBase`） |

求值入口：`EventModel.BeginEvent` 后置补丁 → `EvaluateAncientEncounter`。

- 只认 `AncientEventModel` 且 `is TouhouAncientBase`；原版先古之民不会触发。
- `GameMode.AreAchievementsAndEpochsLocked()` 为真（每日/自定义）时跳过。
- 多人只处理本机账号（`LocalContext.IsMe`）。
- 解锁时 `ObtainEpoch` + 写入 `player.DiscoveredEpochs`，保留结算页 `NGainEpochVfx`；揭示仍由玩家点击。

## 6. 注册

所有节点在 `TouhouAncientTimelineContent.Register()` 里声明，`Entry.Init()` 中先 `Register()` 再 `Initialize()`：

```csharp
TouhouAncientTimelineRegistry.Register<TouhouSanaeEpoch>(
    TouhouAncientTimelineEra.Door(0),
    TouhouTimelineUnlock.Ancient<KotiyaSanaeAncient>(),
    position: 3);

TouhouAncientTimelineRegistry.Register<TouhouMamizouEpoch>(
    TouhouAncientTimelineEra.Door(1),
    TouhouTimelineUnlock.Ancient<FutatsuiwaMamizouAncient>(),
    position: 2);
```

`Initialize()` 依次：读原版 `_epochTypeDictionary` 登记占用格位 → 写入故事/节点字典 → 追加 `_allEpochs` → 分配布局 → 刷新 `_allEpochIds`。注册在 `Initialize()` 后被冻结。

## 7. 节点与资源

```csharp
public sealed class TouhouSanaeEpoch : TouhouAncientTimeline
{
    protected override string TimelineId => "TOUHOUANCIENTS_SANAE";
    protected override string? PortraitPath => "res://images/epoch/sanae.png";
}
```

- `TimelineId` 建议带 `TOUHOUANCIENTS_` 前缀。
- 头像解析：`SlotPortraitPath` → 原版 atlas（若存在）→ `PortraitPath` → `images/timeline/epoch_portraits/{id小写}.png`。
- 详情图：`PortraitPath` → 约定 PNG。
- `PortraitPath` 支持 `res://` 绝对路径或相对 `images/` 的路径。
- 文案键：`epochs` 表 `{Id}.title` / `.description` / `.unlockInfo` / `.unlockText`。
- `unlockInfo` 支持原版变量 `{IsRevealed:已解锁文案|未解锁文案}`。

## 8. 存档与槽位

- `ProgressSaveManager.LoadProgress` 与 `NTimelineScreen.OnSubmenuOpened` 后置补丁调用 `EnsureSlots()`，为全部 Mod 节点补槽。
- 补槽用 `ProgressState.UnlockSlot(id)`：缺条目建 `NotObtained`、`ObtainedNoSlot` 提升为 `Obtained`。
- 默认解锁节点在同一次 `EnsureSlots` 中被置为 `Obtained`。
- `ClearAllProgress()` 直接删条目回到首次安装状态；`touhou-timeline-reset` 控制台命令调用它。
- 移除 Mod 后，未知 Id 会被原版 `ParseEpochs` 保留到 `_unknownEpochs` 并原样写回。

## 9. 风险

1. 私有字段反射会随游戏版本变动；失败只 `Log.Error`，不阻断启动。
2. 自建列整数只决定列顺序，无法插到原版列中间。
3. 多人要求双方 Mod 版本一致（`ModelIdSerializationCache` hash 校验）。
4. 原版 `EpochModel` 没有 `EraName` 属性；不要给它写 Harmony 补丁（曾导致 `PatchAll` 抛异常中断初始化）。
5. 所有补丁类都带 `Prepare()`，目标缺失时跳过。

## 10. 验证清单

- `dotnet build TouhouAncients.csproj -t:Compile` 通过。
- 启动日志出现 `Timeline registered: N epoch(s).`，无 `Timeline registration failed`。
- 时间线出现自建门扉列与两个节点，读档后节点不消失。
- 遇到早苗 / 猯藏后对应节点变为已获得，点开后 `QueueUnlocks()` 正常执行。
- `unlock all` 能解锁全部 Mod 节点（`_allEpochIds` 已追加）。
